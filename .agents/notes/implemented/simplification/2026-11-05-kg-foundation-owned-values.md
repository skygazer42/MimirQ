# Agent Note: KG 基础数据与仓储的函数归属

Status: implemented

## Problem

KG 仓储持有真实 Session 和向量适配器，但部分重定向计算只使用参数，仍依附在实例上。数据集 ACL 查询与置信度分桶在相邻所有者重复实现；内部已构造的计数、路径和快照又被重复解析，真实原始边界不容易识别。

## Decision

五个纯重定向计算函数归同一 repository 模块，AliasRepository 继续持有 Session，数据库加载与有状态入口保留。RelationRepository 复用既有的规范数据集 ACL 查询函数，保留查询、延迟导入、参数归一化和调用时点。

置信度分桶由 dependency-light 的 provenance 持有，搜索工具沿用原公开名称直接导出同一函数，不增加转发包装。两份原实现的转换、默认阈值、异常、比较顺序与 NaN 行为一致；不同策略的提取 clamp 不归入分桶规则。

真实 ORM 和本地结果的声明字段直接读取。手工导入的向量状态声明原有固定计数与可选错误字段；原始向量和 JSON 转换继续留在边界。其唯一 flush 包装的实际 Session 在此前入库流程已要求 flush，向量写回直接调用同一个方法，不把缺失资源伪装成成功。

快照和 provenance 的外部 dict、对象、UUID、数值与可空解析保持。只直接传递真实生产者已产生的 native 计数和字符串；哈希、字段、JSON、样本数、排序、平局、ACL、租户、事务、缓存失效及错误策略保持。任务结果的三份同形投影复用一个返回新字典的模块函数，日志和模型 schema 保持。

## Alternatives considered

把全部仓储改成无状态函数能进一步减少类，但会掩盖真实 Session、Milvus 适配器和事务寿命，因此只迁移不读取实例状态的计算。

为内部与原始图谱统一新增模型或 Context 能减少宽泛类型，却会同时改变导入、序列化和失败边界。本轮复用现有模型，仅给本地固定记录声明必要类型。

让 provenance 调用搜索工具中的分桶实现可以少改一个定义，但会给原本轻量的 provenance 引入 ORM 依赖；因此由轻量所有者持有规则，已有搜索名称直接导出。

## Consequences

纯计算、数据访问与原始值的职责更清楚。直接字段读取依赖当前实际生产者；未来接入其他对象时需要重新核对。缓存、模型、事务和公共 API 不因函数归属调整改变策略。

检索命中的 [KG 查询扩展所有者](../architecture/2026-11-03-kg-query-expansion-owner.md)持有另一条编排边界，[语料缓存失效事务](../bug-fix/2026-11-03-corpus-cache-invalidation-transaction.md)持有跨服务提交规则；两项决定继续保留，本记录不替代。原始图谱与共享标量转换的既有异常区别同样保留。

验证限于完整源码、真实调用者、已安装 SDK 源码、Ruff、格式、隔离 stdlib AST311／哈希／静态契约。不新增、扩写或运行 Python 测试，不导入或执行应用、SDK、模型、数据库、服务、真实正则或业务运行时。
