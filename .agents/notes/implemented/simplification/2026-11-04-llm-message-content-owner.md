# Agent Note: LLM 消息文本转换所有者

Status: implemented

## Problem

`factory.py` 与 `prompt_cache.py` 各自把第三方消息内容转换为文本，分支和拼接顺序完全相同。响应提取和缓存长度判断若分别修改，可能对同一条多段消息产生不同文本。

## Decision

`app.rag.llm.prompt_cache.message_content_to_text` 持有现有转换规则。模型响应与流式分块直接调用它；提示词缓存的长度判断和文本块构造也调用它。字符串直接返回，列表按原顺序保留字符串与 `type=text` 的字典块，其他值按原规则转为文本。

模型客户端、LangChain 插件、回退链及 ContextVar 元数据继续由原类持有。消息转换不增加校验、修复或降级规则；只有真实类型确定的内部字段退出重复转换。外部模型元数据和内容块仍保留原边界处理。

## Alternatives considered

- 保留两个私有函数能让调用位置局部自足，但算法没有差异且需要同步维护，因此采用既有提示词缓存模块作为所有者。
- 再新建一个消息工具模块能让模块名更通用，但会增加一个只有这一条规则的层次，因此直接使用已承担内容解释的 `prompt_cache.py`。

## Consequences

消息转文本只有一份实现；后续修改需要同时核对普通调用、流式输出与缓存标注。如果供应商要求不同的内容解释，应在其协议边界明确差异。提示词字面量、模型选择与回退顺序、首次输出后的失败、取消、预算、HTTP 资源策略和缓存阈值保持现状。Python 测试与模型运行时不执行，本批以 Ruff、AST、签名、字面量和源码引用核对为依据。
