# Agent Note: 解析辅助逻辑直接使用实际生产者的数据

Status: implemented

## Problem

解析辅助逻辑已经完成外部元数据和提供方返回值的解析，却又转换本地刚生成的计数、分数和固定记录。噪声候选、阅读顺序、产物结果和 Markdown 图片引用都有明确字段，消费者仍把它们当作未知字典。PDF 质量评分重复初始化元数据，并探测必然存在的阅读顺序分数。SmallModelRuntime 还把无状态私有工具和清单、缓存操作放在一起，使实例状态的实际用途不够清楚。

## Decision

预处理与质量链保留现有模块函数、结果记录、RapidOCR 服务和缓存 ONNX 加载器。只有实际生产者已建立原生类型时，消费者才直接读取：包括内置 float/int 解析、len/count/enumerate、本地计数、字节长度、归一化旋转值和固定字典构造。噪声候选与阅读顺序记录用 TypedDict 声明已有字段，运行时仍是普通字典。

无状态处理与 ZIP 的实际依赖由[流程函数所有者](../architecture/2026-11-13-document-pipeline-function-owners.md)接管；ZipImageProcessor 仅保留固定上游实际使用的两个同函数绑定，原提取／清理／上传规则继续在真实拥有者中执行。子进程、图片与配置的确认失败路径见[资源失败收尾](../bug-fix/2026-11-13-parser-failure-resource-ownership.md)，不把这些行为修复描述为原样保留。

没有接入生产入口的行业噪声 miner／模式包与磁盘文档导出工具按[未接入工具退出](2026-11-13-retire-unwired-parsing-utilities.md)裁剪；实际在线清洗、十二文件步骤、噪声检测、模型和下载字节渲染保留。本篇的生产者原则不构成恢复退休工具的依据。

阅读顺序的几何数据仍先经过原始元数据或正则解析，再交给私有 _Tag/_Block。原始解析、哨兵、公式、整数到浮点数的显式运算、边界处理和排序保持。PDF 质量评分复用既有元数据初始化函数，直接读取实际结果里的 reading_order_score；真实输入边界的容错规则保留。

NumPy/OpenCV 归约、ONNX shape/dtype/feeds、图片/PDF/HTTP/文件处理、模型可用性以及缓存生命周期保留各自的转换和失败边界。LoadedModel 的 backend 与 name 来自同一加载器的字面值和固定调用。图片预处理直接读取已声明的 Settings 字段，同时保留全部 bool/int/float/str 转换、默认值和原始提供方／元数据检查。

SmallModelRuntime 保留清单、规格选择、缓存、CPU 策略、提供方选择及 resolve/load 方法。路径大小、兆字节换算、可用提供方查询、CPU 回退查询和状态记录构造五个无状态私有工具移到同文件模块函数；原操作和边界保持，实例方法直接调用。仓库调用方只使用实际 resolve/load API，没有外部调用需要迁移这些私有方法。

ZipImageProcessor 保留导出实例、logger 和类钩子：API 与 MinerU 使用这个资源 API，解析适配器还调用其 ZIP 工具。提取上限、路径约束、临时文件、上传、Markdown 选择和引用替换保持。ZIP 与图表增强直接读取声明的 Settings 字段，保留值转换。产物和 ZIP 归一化继续分开，它们接受的引用语法、选择规则和迭代顺序不同。

增强与文档元素消费者直接读取本地生成的图表计数、表格尺寸、章节级别及已解析的页码／坐标。表格尺寸来自 len，图片索引来自 enumerate，方向置信度来自 _softmax 的原生浮点数列表；NumPy 归约及输出形状转换仍在边界完成。产物结果和图片引用以 TypedDict 声明已有字段，图片解析器使用实际 Callable 签名，可空片段明确检查 None。DOCX 类型注解在 TYPE_CHECKING 下引用 docx.document.Document，现有 docx.Document 工厂调用保持。编码探测、BOM 与回退顺序不变，消费者直接读取已解析的置信度和编码名称。

版面块的页码、正文和 bbox 原值读取由已有 block_schema 持有，三个真实多消费者共用同一字段优先级；零、False、None 和负坐标按原规则处理。caption 候选保存已验证几何，header/footer 只保留实际消费的缺失几何标记；reading-order 的无效项已经按 enumerate 索引追加，不再按相同索引二次排序。原有几何阈值、分栏／同分顺序、受保护 kind 和可选模型降级保持。

表格渲染、轻量 profile 和完整 cell extraction 继续独立，因为空表头接受规则、分配成本和格式转义不同。只退出无消费者或单次包装、重复内部转型；原始 OCR 文本的 0／False 以真实文本保留，None 仍为空，bbox 数值只捕获标准转换异常，未知 RuntimeError 可见。可选 OCR 失败、模型两次 resolve 且禁止下载、跨页相邻顺序和原始 metadata 边界保持。

这与[解析适配器的生产者原则](2026-11-05-parser-adapter-helper-ownership.md)一致，覆盖解析链的另一部分。该适配器决定和此前已关闭的增强／模型工具继续有效。

质量门禁内部记录合回唯一构造者并退出任意对象通用序列化，具体边界由[质量结果所有者](2026-11-13-parse-quality-decision-owner.md)接管；文本评分同样直接序列化自身原生计数及分数。外部 API 的 Pydantic 契约不受影响，旧私有导入不建立兼容壳。

门禁原始 metadata 仍按已有字段优先级解析，可选信号、低置信度列表与零预算保持。四处计数共享同一非负化规则，替代嵌套赋值表达式；表格 shape 中合法零行／零列优先于后备字段，不再因真值判断被另一个计数替代。原评分权重、惩罚、阈值、标记与外部元数据名称保持。

本地解析缓存仍由租户目录的调用方隔离，缓存键和存储 schema、TTL 为零的含义、过期删除与临时文件后原子替换保持。读取直接依靠文件操作的预期异常处理，退出重复 exists／is_file 预查；损坏 JSON、结构、时间戳及真实 OSError 仍是可重建缓存未命中并记录类型，未知实现异常继续向现有流程入口传播。不把缺失时间戳改为 epoch 零，不吞任意异常，也不增加第二套存储或新配置。

RapidOCR 的加载入口返回已经取得的模型，识别函数要求该模型，不在识别时把未初始化状态默认为空成功。服务仍拥有原懒加载缓存；借用的外部图片不关闭，PDF 栅格化产生的图片由创建方在 finally 显式关闭。模型加载错误仍按原异常转换，识别／PDF 可选失败仍按原 warning 和空结果处理；没有承诺并发初始化只发生一次或能强停同步模型调用。

## Alternatives considered

删除所有标注为数值的字段转换能进一步缩短代码，但 NumPy/OpenCV 归约、提供方数组、公开记录和原始元数据可能包含非原生或未校验的值。因此只删除已追溯到具体原生生产者的重复转换，保留 JSON 序列化和实际边界转换。

共享预处理 Context 或 manager 能集中记账，但现有函数已经分别表达文件、图片、提供方与质量职责，因此继续使用现有模块。资源对象和不可变记录保留原职责，无需兼容包装或额外微模块。

把 Runtime 或 ZIP 的全部方法移到模块会破坏真实清单／缓存职责，以及调用方使用的类／实例 API，因此只移动五个内部无状态工具。合并产物和 ZIP 归一化也会改变可接受语法或顺序，继续分别保留原算法。

## Consequences

原生值和固定字段的来源更清楚，剩余 Runtime 方法直接显示其状态职责。五个私有工具归属原模块，无须迁移模块外调用。文本、编码、哈希、字节数、处理和候选顺序、分数与并列优先级、旋转和坐标输出、元数据键及复制、阈值、日志、异常与产物行为保持。中央清单和验收记录由集成端维护。

验证包含完整基线／候选源码的精确限定 AST 比较、实际生产者／调用方和已安装 SDK 源码核对、Ruff 与 Python 3.11 AST。未新增、扩写或运行 Python 测试，未导入应用或执行模型、OCR、图片／数组处理、HTTP、服务、网络或 CLI。这些静态证据不衡量真实图片质量或模型可用性。

质量与缓存续作使用冻结原文及当前源码的 AST 隔离执行、原生标准库数据类和假 Path／os／logger，核对评分、门禁分级、零值、深层副本、缓存命中／过期／损坏、原子替换和意外异常传播。完整应用冷导入另作路由与 OpenAPI 比较，不启动生命周期或处理请求；离线假资源不证明真实磁盘并发、解析质量、SDK 或服务运行通过。合并模块后旧测试的私有导入仍需后续维护，当前按用户要求不修改或运行。
