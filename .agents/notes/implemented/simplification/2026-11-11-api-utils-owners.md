# Agent Note: API 工具的公共入口与文件清理所有者

Status: implemented

普通包形式和域外公共导入规则由[领域包入口](../architecture/2026-11-11-domain-package-public-api.md)更新；本篇继续持有工具实现、资源关闭与管线数据处理的决定。

URL 普通格式错误文案及标准库返回值异常政策由[URL 入口错误收敛](../architecture/2026-11-11-url-input-error-policy.md)更新；本篇的固定目标传递、权限顺序、跳转和资源管理决定保持。

## Problem

上传和 URL 下载各自维护同一套有界文件清理策略，修改超时或取消处理需要同时更新两处。文件名、路径和固定 DNS 目标已被多个模块使用，却仍用私有名称及重复别名导入。文件响应还有两个只传递默认 attachment 的包装，使同类调用采用不同入口。

管线参数转换把字段合并、条件校验和默认返回嵌套在一起，data 的阶段含义不清楚。仅确认每个判断有来源不足以证明主流程容易维护。

URL 模块的公共流程埋在解析辅助函数之后。下载同时追踪 completed、redirect_url 和 result，并把同一次响应的状态／长度检查、写入、结果构造分在三个函数里，阅读时需要往返查找。

下载仅有一个生产调用方，而且它总是传齐大小、超时与跳转配置；两层选项对象却把这些值再次声明为可空并回填默认值，制造额外状态和判空路径。

同一条网址入库链在入口校验后只保留原始字符串，下载时重新校验并解析 DNS，丢掉了已经得到的固定目标。跳转还同时维护“已跟随次数”和“最大次数”，将一个预算表达成两个相关状态。

## Decision

upload.py 归到 file_io.py，持有上传保存、路径、哈希及部分文件清理。两处清理合成 cleanup_partial_file(path, operation=...)，保留五秒取消屏蔽、missing_ok、OSError 日志及调用方原有异常边界；操作名保留上传／下载的诊断信息。上传资源关闭顺序与 URL 流式文件关闭分别留在各自实际资源拥有者，不引入通用传输执行器。

跨模块文件操作使用 normalize_upload_key、normalize_upload_path_parts 和 sanitize_upload_filename。URL 的固定目标类型、校验与客户端工厂使用公共名称。十七个生产调用方直接导入实际所有者，删除旧名与重复别名，不保留转发入口。

response_headers.py 保留原有 file_response_headers 和 set_content_disposition，两个仅转发默认值的下载包装退出。无 I/O 的重定向函数使用同步声明；下载请求选项与解析后选项使用不同局部名称。包说明文件及无调用用途的 __all__ 退出，沿用项目现有命名空间包。六个原文件收敛为五个模块。

document_pipeline_input.py 继续持有 JSON、覆盖参数和 HTTP 错误边界。字段收集、已提供值覆盖、最终 Pydantic 校验及内部选项构造同层顺序执行，pipeline_values、validated_pipeline 和 options 分别表达阶段含义；空字段也经过同一构造路径，不另设默认对象返回。用户完成简化后，真实可省略表单 None 在共同入口处理一次；长度直接按原始 JSON 文本计算，不先 strip，也不接受空串／null／none／undefined 作为缺省兼容。JSON 与合并字段各只在实际 Pydantic 调用处窄捕 ValidationError，转换为原400；内部 PipelineOptions 构建和执行校验在捕获范围外，False与0覆盖保持。公共错误响应说明与文件响应头分别保留，因为调用职责不同。管线归属的其他决定仍由[API 调用与输入所有者](2026-11-10-api-route-and-input-owners.md)持有，不吸收或归档该笔记。此前退出的 pipeline_options.py 不恢复。

URL 的所有 DNS 答案校验、逐跳验证、Host／SNI、跨 origin 敏感头处理和字节限制保持。真正可选的输入、合法零值和关闭值保持原语义；没有新增重试、默认成功或兼容分支。

URL 公共记录与入口按阅读顺序放在模块前部，单次解析记录退出，网址解析直接归到 validate_fetch_target。入口返回的冻结 ValidatedFetchTarget 经 document_ingestion_sources 传到下载器，初始地址只校验和解析一次，直接固定首次验证的 IP。数据集写权限仍在入口校验之后、下载之前检查；来源、扩展名和元数据继续使用 target.raw。下载器只接收已验证目标，不同时猜测字符串和目标对象，也不提供兼容分支。

IP 直接解析以保留 IPv6 网卡标识，域名通过 asyncio 的 getaddrinfo 异步解析并按原字符串保序去重；单次同步包装退出，DNS 与地址转换使用原生异常。URL 在入口去首尾空白并直接作为 raw 返回，scheme 使用解析器已规范化的值，连接网址用 ParseResult.geturl() 构造。响应检查、限量写入和元数据构造归到 _save_download_response。下载主循环正常保存后 break，待响应与客户端关闭后返回；跳转在旧连接关闭后重新校验目标，按协议、域名和端口决定凭据是否保留。跳转只维护一个剩余预算，错误顺序不变。completed 标记、重复初始校验和重复正常路径判断退出，错误与取消仍清理文件后传播。

download_url_to_path 直接要求 max_bytes、timeout_sec 和 follow_redirects，document_ingestion_sources 原有的五个参数表达式逐一保持并直接传入；URLDownloadOptions、_DownloadOptions 和回填函数退出。user_agent 与 extra_headers 保留真实可选语义，请求头的默认值和过滤在一个函数完成。跳转由状态码明确分流，跳转解析仅处理跳转且必定返回网址，不再用 None 表示普通响应。HTTP 外部接口保持，下载内部 Python 签名随唯一生产调用方迁移。

白名单处理信任入口已经规范化的主机和 CSV 规则，删除重复去空白和空规则分支；请求头两个相同的拒绝路径合并。DNS 使用 dict.fromkeys 保序去重，HTTPX 已过滤的空数据块不再重复判断。Location 在外部响应边界统一规范化再验证，ETag 只保留真实可空检查与定长切片，没有新增默认成功或备用地址。

## Alternatives considered

- 所有主机统一经过 getaddrinfo 可以省去 IP 分类分支，但系统会将 IPv6 网卡标识移到 sockaddr 的 scope_id，旧 IP 路径直接保留该标识；因此保留 literal 快路径，只删除同步包装，不增加 scope 补丁逻辑。
- 保留下载包装能突出下载用途，但其签名和实现仅转发已存在的 attachment 默认值；统一入口可减少同类调用的写法，inline 等真实差异仍由参数明确给出。
- 单建文件清理模块能让清理函数独立，但当前只有上传和下载两处相同使用，文件操作已有明确所有者，新增小文件会多一个维护位置。
- 合并全部 HTTP 工具能进一步减少数量，但管线解析、响应说明、文件资源与 URL 安全分别有真实使用方；合并会扩大每次改动和导入涉及的职责。
- 仅在覆盖字段非空时再次校验，能省去无覆盖路径的一次模型往返；当前选择合并边界统一校验，让正常路径同层汇合。现有参数清理和插件引用规范化在稳定配置下幂等，没有导入或 I/O，成本与契约核对后保留这一取舍。
- 保留三个独立响应辅助函数能单独调用，但当前只有同一次下载按固定顺序使用它们；合并为完整响应保存阶段能直接看到状态、配额、关闭和结果的关系。没有新增下载执行器、资源包装类或更多子模块。
- 保留可空选项容器能让调用方省略配置，但当前唯一生产调用方每次都提供完整配置，容器与解析后的第二种容器没有独立用途；必填参数能直接表达实际契约。
- 下载器继续接受原始字符串并重复验证，可供未知调用者单独传网址，但现有生产链已经拥有验证结果；沿链传递确定目标能固定同一个 IP，并避免两次 DNS 结果与状态互相影响。跳转地址仍属于新的外部输入，继续独立校验。

## Consequences

清理规则只有一个维护点，跨模块调用使用明确的公共名称，文件响应不再依赖相同默认值的两套入口。管线流程使用相同的最终构造路径，代码行数不作为可读性目标。无覆盖输入多一次本地模型校验与序列化；单一基础配置的百次样本均值由每次 22.6 微秒变为 43.1 微秒，该样本不代表业务负载或吞吐。旧内部导入和测试补丁点随符号退出，不设置兼容壳；按用户要求，本批不改、不跑 Python 测试。

资源和 URL 行为经过源码、装配与独立审阅核对，未执行真实上传、取消、网络下载、模型或数据库业务。若未来上传与下载确有不同清理契约，再据实际差异调整，不为未来差异增加选项或备用实现。

URL 模块保留两种实际结果记录，下载配置直接使用明确参数，None 比较由必填参数整理前的十一处减至六处。剩余判断有真实可选 Header、URL 端口与远端响应来源；异常分支负责外部解析、网络错误转换、资源关闭和取消清理。测试中的 _download_result、_validated_redirect_url、_download_options、_resolve_host_ips 旧导入／补丁点随前序内部实现退出，相关测试需要独立迁移，包含一处已知收集期导入失败；按用户要求本批不修改或运行测试，也不为旧测试名恢复兼容壳。

初始目标以请求入口验证时的 IP 为准，不在下载前切换到第二次 DNS 结果；稳定 DNS 下的离线对照保持传输与文件结果，不宣称动态 DNS 场景仍会选择旧实现的第二次结果。输入类型与调用方同步迁移，旧测试的字符串下载调用需要在测试维护任务中调整。
