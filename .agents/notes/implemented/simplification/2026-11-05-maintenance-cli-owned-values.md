# Agent Note: 运维脚本的参数与内部结果归属

Status: implemented

## Problem

补写向量、嵌入迁移、恢复验证和性能脚本重复转换 argparse 已解析的字符串、整数、浮点数和开关。部分渲染或后续步骤又重新校验同一模块及既有服务已经构造好的结果，主流程难以看清真正不可信的数据从哪里进入。

## Decision

切块离线评估脚本的 coverage 依赖后续直接指向实际计算 owner，见[服务输入实际所有者](2026-11-14-service-input-owners.md)；仅迁移原 import 与唯一调用，既有参数、其他脚本业务及本篇资源边界保留。

CLI 继续由原 argparse 声明解析和校验，业务步骤直接使用其结果。零值对应默认值、负数截断、最小随机字节数、dry-run、execute 和可选批量参数的含义保持。三个 UUID 参数回调直接消费解析器传入的字符串，保留原错误转换及配置来源的 UUID 校验。

MinIO 指标模块复用其浮点转换、计数器和 OpSummary 构造结果；JSONL 读取函数标出各分支实际返回的列表，调用方直接取得这份局部列表。百分比只格式化实际浮点字段，不再把不可能的内部格式错误显示成 n/a。外部记录、可选 SDK、桶统计和 JSON 读取的既定失败策略保持。

恢复验证只在现有 index-audit 请求已确认成功且 body 为对象之后读取该 body。性能差异渲染直接读取既有 perf_suite_diff_service 始终构造的门禁、案例和分位结果。文件输入仍在原 JSON 边界校验；服务的计算、排序、阈值及响应格式保持。正常 subprocess 捕获结果按 text=True 的字符串契约消费，超时分支的原始输出处理保留。

五个原有类保持，其中 BenchmarkResults 持有真实累计状态；补齐实际空返回和迭代器签名。PowerShell 演示脚本与 Docker 子网选择器保留原始字节；不为统一写法引入脚本管理器、共享微型模块或新的依赖。

## Verification

13 个原始 owner、2,636 行全文阅读，12 个 Python 文件使用 Python 3.11 stdlib AST 与 Ruff 检查；PowerShell 仅执行静态 ParseFile，不调用脚本。固定源码核对 84 个函数的参数、默认值和装饰器、五个类、112 处 argparse 声明以及现有资源清理。内部表达式的依据分别来自实际参数声明、调用方、计数器、HTTP/进程结果和性能差异服务，独立复审另存外部证据。

不新增、扩写或运行 Python 测试，不导入或运行这些 CLI、业务函数、SDK、模型、数据库、业务正则和数据处理流程。静态证据不证明实际迁移、上传、恢复、Kubernetes 故障注入或性能结果。

## Alternatives considered

把相似的 HTTP、UUID 或报告函数集中到一个新工具模块，可以继续减少表面重复，但会耦合独立 CLI 的 SDK 初始化、错误文案和协议策略。保留各自真实边界，仅退休已知值的重复转换，避免新增跨脚本依赖。

逐处保留转换和结果兜底，能够继续容忍不符合当前调用契约的人工构造对象，但会让已解析参数与外部原始数据看起来同样不可信。使用现有具体所有者，并保留真实输入边界和既定失败策略，使后续维护可以顺序追踪数据来源。

## Consequences

相同的 CLI 参数采用一致的直接取值方式，真实外部数据的转换仍留在入口。调用契约变动时需要同步检查实际所有者与调用方，不能把静态类型当成上游行为的替代证明。没有新增保护分支、静默成功、重试、兼容层、配置或二次写入。
