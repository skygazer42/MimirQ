# Agent Note: 用户文档元数据的唯一合并实现

Status: implemented

## Problem

`document_metadata_service.py` 保留了一份用户元数据合并、标签和备注归一化实现，与 `document_user_metadata.py` 重复。现行上传、批量更新和单文档修改都直接调用后者；前者只被列表与详情读取流程用于临时补充统计。未使用的副本让同一规则有两个维护位置。

## Decision

用户元数据合并规则只由 `document_user_metadata.py` 持有。删除旧服务中无 Git 跟踪调用方的合并入口和三个私有辅助函数，保留现行调用路径。旧服务继续持有 `build_runtime_document_metadata` 和 `attach_runtime_document_metadata`，从已有元素补充只读响应统计，不承担用户写入规则。

合并／替换模式、None 删除、标签去重顺序、长度和数量限制以及备注清理保持现有规则。授权、元数据持久化、commit／refresh 与审计错误处理仍由原操作模块承担。

## Alternatives considered

保留旧入口并转发到新所有者能兼容旧导入；完整 Git 跟踪调用和笔记检索未发现该导入，项目内全部写入已经迁移，因此额外转发会留下一个没有消费者的入口。把规则并回响应统计服务可以少一个模块，但会再次混合用户写入与临时响应补充的职责，因此保持现行所有者。

## Consequences

只退出无调用的四个函数；剩余运行时元数据函数的语法树和公共读取调用保持原样。与实际合并实现的对比只需要解释局部变量名差异，未新增通用归一化框架。没有新增、修改或运行 Python 测试；验证限于 Ruff、Python 3.11 语法、源码和调用契约，未声称数据库运行时回归。

活跃笔记按模块名与用户元数据关键词检索未发现同一决定；本记录不替代权限、事务或文档入库的既有所有者约定。
