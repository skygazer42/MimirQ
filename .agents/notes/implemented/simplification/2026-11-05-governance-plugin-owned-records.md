# Agent Note: 政务插件的来源读取与内部记录

Status: implemented

## Problem

政务插件入口和事项模块各有一份相同的来源字段读取。事项候选、章节和实体都由本模块生成，消费端仍把它们当成未知字典，重复转换字符串、复制临时列表和探测必填键。样例生成器也重复书写同一个三元组类型。

## Decision

`gov_service_items._source_name` 持有现有来源规则，插件入口直接导入该函数并保留 `_source` 绑定。来源字段的优先级、用户元数据回退、空值处理保持。已经确定为字典的用户元数据只处理一次。

事项候选用同文件的 TypedDict 声明实际生成的字段，仍构造原字典。后续直接读取标题、别名、字段、指纹、编号和偏移；重复事项的变体计数直接使用前一轮对同一候选集合生成的键。候选中的列表和字典只在本轮消费，不再复制后立即丢弃。Document 元数据的构造与复制仍沿原路径。

章节返回 `list[dict[str, str]]`，其三个键由本模块的章节构造器及操作入口记录完整生成。消费端直接读取。实体去重只消费 `_entity` 的完整返回记录或 None；实体类型由同模块调用点的非空字面量提供，名称仍经过原有清理、casefold 和长度限制。Markdown 表头的后置重复守卫由前面的成功匹配与 break 保证，退出重复判断。

私有文本函数直接处理实际调用方已生成的字符串，保留原 strip、分隔、标记、URL 和正则规则。原始元数据、JSON、字段值、参数数值、SDK 文档内容以及缺失文件仍在原边界处理。样例的 DimensionProfile 仅表达既有三元组，不改变样例选择、证据、比例、缓存或输出协议。

## Alternatives considered

将候选改成 dataclass 可以使用属性访问，但需要替换现有字典构造。TypedDict 已能说明字段并保留原值的形式。

保留两份来源函数可以少改一行导入，但规则继续有两个维护位置。现有模块已经被插件入口导入，复用实际所有者不增加模块或包装层。

删除所有转换可以进一步缩短代码，但插件元数据、JSON、配置和 SDK 对象仍提供原始值；当前只清理有实际生产者保证的内部值。

## Consequences

来源规则只维护一份，阅读主流程时能看清已生成的记录和外部输入。来源优先级、正则字面量、稳定 ID、hash 种子、顺序、预算、偏移、元数据键和外部格式保持。

[插件合同与已构造结果](2026-11-05-plugin-contract-owned-results.md)处理平台运行层的输入边界，本篇处理具体政务插件内部的记录。原始插件合同、安全校验、加载与资源策略不由本篇替代。共享标量转换和结构化 chunker 笔记处理其他所有者，没有同一函数或决定需要合并。
