# Agent Note: 检索编排内部记录与原始输入边界

Status: implemented

## Problem

检索契约、插件锚点和后重排校准使用本地构造的固定字段字典，但后续代码继续按缺字段的原始字典读取并重复转换数值。层级文档查询明确返回 `DocumentChunk`，转换器却把声明字段当作未知对象探测。这使编排规则与输入兼容逻辑混在一起。

## Decision

检索契约、启用或禁用的插件锚点配置、后重排校准行使用 TypedDict，继续返回原字典。实际构造器保证的字段直接读取，本地已经完成转换的布尔值、计数和浮点数直接传递。插件策略仍验证 schema、启用值、字段列表和原始数值；校准行仍解析 retrieval/rerank 原始分数并保留原异常默认值。

校准保留 min/max 公式、浮点运算顺序、重复 ID 的覆盖顺序、元数据复制和文档类型过滤。排序中的 `or -1.0`、零值默认与原索引并列规则保留。后重排阶段继续解析原始 stage 数量和回调结果，只去掉由这些解析、本地累计或 `len` 已确定的重复转换。

层级查询的参数和返回值标注实际 `Session` 与 `DocumentChunk`，转换器直接读取 ORM 声明字段；可空位置字段、原始 JSON 元数据、pipeline 匹配、租户过滤和 `finally` 关闭策略保留。主编排的 KG 注入接收另一种原始行边界，继续保留其现有探测和过滤。

106 处 Settings 字段存在性回退改为已声明属性。Settings 不启用赋值验证，因此原始值转换、`or` 默认、范围限制与转换异常处理继续存在。注入式路由支持函数仍按原约定解析回调字典，不能把本地固定记录的保证扩展到这些回调。

`RetrievalRuntimeState`、查询计划、23 个运行阶段、线程池、缓存、会话、回调和原有钩子保持。结果阶段声明实际必返字典，并移除无条件返回之后的不可达语句。显式再导出的导入形式遵守现有 Ruff 规则，绑定与顺序不变。

## Alternatives considered

合并 `query_routing` 与旧路由支持模块可以减少相似代码，但后者注入回调并保留独立的值转换边界，前者还处理流式复杂度覆盖。整体替换会改变调用和失败契约，因此保留入口，只明确各自已经构造的内部值。

把所有编排输出换成 dataclass 可以消除字典访问，但需要迁移当前结果、指标和回调协议。TypedDict 表达固定字段，同时保留原对象形状和复制规则。

统一删除基于注解的转换可以进一步缩短代码，但可变 Settings、插件策略、元数据、stage 配置和 provider 回调仍有原始值解析职责。当前只删除真实生产者已确定的转换。

## Consequences

契约与排序记录的来源更清楚，原始数据仍由原边界负责。回调字典与动态运行状态继续需要现有兼容处理；如果以后改变记录生产者或引入另一种 ORM 行实现，需要重新检查字段保证。

本次历史审计中，[查询准备所有者](../architecture/2026-11-03-query-preparation-owner.md)与计划和阶段时序部分重叠，[混合检索排名](2026-11-05-hybrid-ranking-owned-values.md)与内部记录原则部分重叠，[重排 provider 回退](../bug-fix/2026-11-03-reranker-provider-fallback-boundary.md)与工厂和回调错误归属部分重叠，[语料与索引内部值](2026-11-05-retrieval-corpus-owned-values.md)与可变 Settings 边界部分重叠；这些决定均保留并互链。KG 查询扩展、结构化 chunk 和运维 Settings 的命中属于其他链路，没有被替代。
