# Agent Note: 前端解析复用已有扫描与规范化所有者

Status: implemented

## Problem

普通块与带范围块分别维护完整的位置标签扫描，标签文本和标签列表也各自实现相同的清理、去重与数量限制。文件扩展名解析器反复构造允许集合并重复返回结构，Markdown 内联扫描又为只使用一次的结果包装单独函数。修改同一规则需要同步多个分支。

## Decision

带范围的位置扫描继续持有标签语法、页码和 raw 范围。普通块入口调用它并投影既有的 id、text、positions 三个字段，保持原对象形状。标签文本只负责分隔，再调用现有 normalizeTags；文件扩展名与允许后端、理由名称在本模块的规则表中声明，保留原别名与未知扩展名策略。

Markdown 现有 token 读取函数直接完成链接、图片、代码和 HTML 的原顺序判断，保留嵌套与转义解析。slug 继续使用 NFKD 与 Unicode 字符规则；模块本身已包含 Unicode 正则字面量，运行时 catch 无法挽救不支持该语法的环境，因此退出这条无效兼容分支。

数据集配置图只向内部生成的非空摘要字符串写数组，节点在已有 addGroup 中构造。健康 Markdown 直接调用既有 primitive-text 所有者，预检 advisory 不再过滤已经设有非空 code 的结果。原始可选字段、unknown metadata、数字兼容转换和显式 false、0 值继续按原规则处理。

## Alternatives considered

保留两份完整扫描便于单独编辑，但两种视图读取同一语法与块归属，分叉没有独立契约。新增通用 parser manager 或共享辅助模块能集中更多代码，却把现有明确所有者拆散；本次只复用已有函数并保留模块边界。统一 UI parser 名称与文件兼容别名看起来更整齐，但两者已有不同输入策略，不能作为等价清理合并。

## Consequences

位置扫描、标签限制和扩展名失败结果只有一处维护。普通块仍有一次必要的对象投影，避免给既有消费者额外泄漏 raw 范围字段。删除的 Markdown 兼容分支不再为不受当前前端支持的运行环境提供隐式 ASCII 降级。

冻结 Git baseline 与当前源的 1,816 组比较覆盖位置扫描和偏移、标签、文件与批量 parser 选择、Markdown 标题和 slug，以及摘要与图呈现结果，全部相同。扫描样本包含 CRLF、中文、连续／无效位置标签、空文本和重复标签。没有为可逆的局部清理新增仓库测试文件；比较脚本与结果保存在本批外部证据目录。

按模块路径、函数名与位置标签机制检索活跃笔记，没有重复所有者、proposed 或 rejected 提案；后端解析器与治理规则的既有记录属于独立边界，本次不吸收或修改其决定。
