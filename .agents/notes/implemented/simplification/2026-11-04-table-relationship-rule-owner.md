# Agent Note: 表关联规则由图规划模块持有

Status: implemented

## Problem

`table_tag_service` 保留一组旧关联推断函数，但当前公开推断入口已经委托给 `table_schema_graph`。旧函数只互相引用，没有注册或外部调用，容易让维护者误改不生效的规则。图规划内部还重复检查刚构造的表、关联、候选和搜索状态字段。

## Decision

表关联推断与候选评分由 `app/services/table_schema_graph.py` 持有。退出旧 TAG 模块中闭合的九个私有函数、一个私有记录和两项常量；现有公开委托及其他 SQL 规划、模型调用函数保持原样。

图模块用本地类型描述自己构造的规范表、关联、候选和搜索状态，直接消费其字段。种子状态含一项关联，扩展只追加关联；评分和结果整理依赖这个实际构造契约。原始表、别名、列、样本行与外部阈值的解析仍在原入口。排序、哈希、成本、搜索预算和歧义判断沿原规则执行。

表格 API 使用实际 `Dataset`、`TenantMember`、`TableId`、FLS 策略和查询结果类型。预览与查询的字段脱敏共用现有投影函数，仍在原来的处理阶段执行审计。LOTUS DataFrame 的列直接迭代；pandas 的列索引禁止布尔求值，旧 `columns or []` 会抛出异常，导致脱敏准备被跳过或结果响应失败。

## Alternatives considered

保留旧推断代码可以减少本次删除量，但现行入口已经不使用它，继续保留会形成两份维护位置。把图规划并回 TAG 模块可以减少一个文件，却使仅分析表结构的调用者依赖 SQL 生成和模型客户端，因此保留现有图模块的职责。

## Consequences

关联规则有一个实际实现位置，内部字段契约可直接阅读。TAG 文件其他职责仍需单独审核；本次删除不代表整文件重构完成。

验证使用完整源码、引用图、构造点和静态契约检查。按用户要求不运行 Python 测试、SQL、工作簿、模型或服务；运行时评分与数据库行为尚未验证。
