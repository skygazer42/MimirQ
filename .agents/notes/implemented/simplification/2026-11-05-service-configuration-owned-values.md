# Agent Note: 配置服务区分自有结果与原始配置

Status: implemented

## Problem

治理继承、入库规则与模板路由把已构造的 Pydantic 对象和 ORM 完整实体继续当作可能缺字段的外部对象读取。模板奖励聚合还对自己初始化的四字段数值记录重复取默认值和转型，掩盖了原始反馈输入与内部累计值之间的边界。

`PipelineOptions` 同时承接原始配置和显式构造的 dataclass，字段注解不会执行校验。若仅凭数字注解删除其序列化转换，会改变已有 metadata 的类型和指纹。

## Decision

七个配置服务直接读取实际治理 schema、入库规则嵌套模型、GovernanceProfile 与 RagConfigTemplate 行的声明字段。原始 JSON、UUID、规则参数、正则、反馈行和奖励 hook 的校验、转换与错误处理继续留在原边界；没有新的错误类型或 HTTP 转换层。

GovernanceProfile.key 的 SQL 契约允许 None；UUID 读取时按 API 已有规则用 custom:<uuid> 表示未命名配置，真实字符串才去空白。继承合并直接消费 schema 提供的列表、字典与 RegexRuleModel，保留父子覆盖、规则顺序、循环／深度拒绝和脚本展示上限。内置声明的顺序、文本和每次调用的独立容器保持。

检索预设的三个选择项共用本模块的大小写归一化规则；多查询试验的键和变体共用本模块的标签归一化规则，保留大小写。两个私有函数分别有三个和两个实际调用点，仍在原字典／构造参数位置执行；原数值、布尔转换、种子、预算、提供者校验和参数求值顺序保持。入库规则继续区分可强制为字符串的覆盖值与只接受 JSON 字符串的数据集缺省，治理引用的控制字符校验继续在归一化之后。

语料 token 直接使用 core.pipeline_versions.get_active_pipeline_hash，退出重复私有实现；原始 ORM JSON 仍先检查是否为字典。三个 embedding_defaults 字段按原顺序使用同一循环归一化，保留键、大小写、空值和字段顺序。dataset_scoped 的真实生产者是 isinstance 与 any 的布尔表达式，直接使用该结果；排序 JSON、schema、哈希长度、失效事务和缺失记录处理保持。

提示模板和 RAG 配置模板的解析入口要求显式提供实验键和用户键，调试记录要求显式提供 epsilon 与 reward_snapshot；十五个生产／既有测试调用均已提供这些字段。真正可省略的模板 ID、模板键、weights 与奖励 hook 继续保留原默认值，字段值仍可为 None，模板选择优先级和返回形状不变。

两个解析器原先完全相同的 _stable_unit_interval 算法只由 prompt_resolver 持有，RAG 配置解析器导入同名函数，保留本模块内可替换绑定。原 seed、SHA-256、字节截取、取模、权重、排序和探索／利用规则不改动。已有真值分支内的 template_key 与必传实验键直接使用字符串契约，不再重复转字符串或补空文本。
模板奖励累计值沿用同一个字典，私有 TypedDict 声明其四个必需字段。数值只在实际 `float` 生产者、局部累计、`round` 或显式 `max/int` 归一化之后退出重复转型。缺省、零值、负数、NaN、排序、种子和副本策略保持。

流水线 metadata 的 int／float／bool 转换继续定义落盘格式；只删除 OCR 数量在本函数已被 `max(0, int(...))` 归一化后的两次最终 int。Settings 的两项掩码和 VECTOR_BACKEND 使用实际声明字段。版本裁剪读取本模块已统一为字典的 payload，仍按原时间字符串、键和上限顺序处理，canonical JSON 与哈希输入不变。

部分 patch 校验器、模板应用、模板缺省选择和内置脚本注册表各自承担实际边界。数据集 RAG 默认值先排除显式请求字段，再解析／应用 strict 可见性规则；有效覆盖统一交给既有 apply_rag_config_patch 合并与重建 ChatRAGConfig。字段名来自无别名／serializer 的实际 DatasetRAGDefaults，dump 后没有 None；不借复用改变合法覆盖顺序、字段集、空覆盖返回原对象或默认优先级。脚本内容继续仅作展示与版本资料，不在入库链执行。

## Alternatives considered

保留两份稳定分流函数可以维持各文件自包含，但相同算法需要两处维护。当前实现的完整 AST 一致，复用已有提示解析器足以承接，不新增工具模块。不同模板的选择顺序和奖励策略仍由各自解析器持有。

- 按类型注解统一删除数值转换，改动更整齐，也能减少重复代码。但 dataclass 不负责运行时归一化，ORM 数值和原始 metadata 也不能据此推定为原生值，因此只采用具体生产者能证明的局部简化。
- 合并 API 与服务的治理映射可以减少字段重复，但它们分别承担 HTTP 输出和继承载荷校验，错误政策不同。这里直接整理现有所有者，不增加共享 Context、兼容包装或配置框架。

- 把不同配置入口统一成通用 coalesce 可以缩短表达式，但检索选择项需要小写、试验标签保留大小写、原始数据集缺省拒绝非字符串，语义不同。只在各模块已有重复字段上复用自身规则，保持数据入口的区别。
## Consequences

入口可以直接区分原始配置与内部记录，模板累计字段也有明确名称。代价是 metadata 和 SDK 边界仍保留必要转换，不能把这份决定理解为整个配置链无需校验。新增绕过这些生产者的输入路径时，需要重新核对归一化边界；不要把原始值直接写入内部累计记录。上述实验与调试参数改为内部必传，其余签名、HTTP 路由、响应、租户条件、事务、资源、缓存与指纹规则不变。
