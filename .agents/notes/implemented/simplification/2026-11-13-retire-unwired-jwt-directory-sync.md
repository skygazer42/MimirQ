# Agent Note: 未接入的 JWT 目录同步分支退出

Status: implemented

## Problem

当前请求身份采用已经选定的本地单用户和单工作空间，JWT 目录同步的入口没有应用、脚本或注册调用。两种同步服务只被这个无入口包装引用，继续整理它们不能改善实际请求路径，还容易误报已经验证了 JWT 到目录同步的集成。

## Decision

删除 jwt_membership_sync.py、jwt_group_sync_service.py、tenant_member_provisioning_service.py 三个构成闭环的无调用模块。引用核查覆盖具名／相对导入、脚本、动态注册与配置，入口函数只有自身定义，两个服务也没有包聚合公开入口。当前本地身份政策由[实际中间件与请求上下文](2026-11-10-http-middleware-responsibilities.md)记录，不恢复已退出的身份分支。

组管理和资源权限继续由真实服务持有。authz_prometheus_metrics 被 dataset_service、document_access 的实际 ACL 检查使用，保持；JWT_GROUPS_CLAIM 仍由 SAML 签发读取，其他 JWT／SAML／账号功能和现有配置声明不在这次删除中改动。不能仅凭模块名前缀连带删除真实消费者或复用配置。

## Alternatives considered

继续保留并重构这三份代码可以为未来目录集成准备实现，但当前不会执行，也没有端到端验证依据。把入口重新接回请求依赖能让这些代码运行，却会改变已经选定的单用户身份策略，属于新的产品和鉴权设计。

删除全部 JWT 配置看起来更彻底，但部分配置仍有 SAML 消费者；清理内部无入口代码不授权顺带更改其他接口或已声明配置。

## Consequences

当前源码少三个未运行的同步模块，不计入新增完成文件数。此前对服务内部假 Session 的比较只是局部实现证据，不再作为它们有生产调用或实际目录同步已验证的依据。原文与 SHA 保存在本批验证快照，覆盖清单保留退役事实，不保留兼容包装。

实际登录、SAML、Dify 集成、权限判断与工作空间选择没有通过这次清理换一种实现。完整应用冷导入、公开模型和 OpenAPI 用于检查组装，真实身份提供方或目录数据库未在本任务连接。需要重新支持多用户目录同步时，应先明确验证身份的入口和事务职责，不能直接把这条无调用分支恢复到本地依赖。
