# Agent Note: 文档服务保留资源所有者，退出无状态缓存门面

Status: implemented

## Problem

解析缓存的类没有初始化或实例状态，两个方法也不读取 self；真正的对象存储资源由现有 MinIO 所有者持有。沿用这个空门面，会让调用方误把它与持有 HTTP 会话、运行配置和 robots 策略的解析器／爬虫类看成同一种结构。

图片、解析策略、字段抽取和记忆服务还在已经完成归一化的局部计数或结果上重复转换；另一些值来自原始 metadata、SDK 或不校验类型的 dataclass，不能仅凭注解同样裁剪。

## Decision

解析缓存的 get/set 直接成为原模块的 get_parse_cache/set_parse_cache 函数，完整业务语句与关键字契约保持，只有名称和未使用的 self 退出。实际 MinIO 所有者、ParseCacheEntry 领域记录、键与 wire 归一化、副本、TTL、大小上限、过期清理和 best-effort 失败政策保留。

处理阶段直接调用两个函数；处理器聚合入口退出旧 singleton 的导入与重导出。既有阶段用例只迁移 getter 的 patch 目标，导入契约表只删除退休的 singleton 行，不增加或运行测试，也不增加旧类兼容外壳。

Docling 会话、MinerU 可变运行配置与异步文件流、robots 缓存和爬虫运行记录保留实际职责。图片与 XML 消费者使用实际 ORM／SDK 所有者，新增导入仅用于类型检查。爬虫降级信息仍是原五字段字典，用私有 TypedDict 表达其固定生产者，日志、去重和错误输出继续使用相同字段。

数值简化只跟随实际 builtin float/int/len、局部累计记录、JWT 整数生产者和返回原协程结果的桥。ORM 数值与原始 SDK score 转换、原始页号中 bool 到 int 的规则、缓存序列化和 int→float 比较仍保留。SSRF 每跳验证、跨来源凭据剥离、XML 防护、ZIP 上限、排序、指纹、轮询、重试、超时、取消和资源关闭不改变。

结构化记忆中的换行错误属于独立授权修复，见[按真实换行分事实](../bug-fix/2026-11-05-structured-memory-newline-splitting.md)。这里以那个固定提交为基线做等价整理，不再次改写任何正则字面量。

## Alternatives considered

- 保留空缓存类可以少迁移几个引用，但该类既不持有客户端，也不管理生命周期，反而掩盖实际 MinIO 所有者，因此在同一类别内完成函数与引用迁移。
- 把所有 parser/cache 类都展平，形式更统一，却会破坏实际会话、配置、警告状态、文件流和 robots 缓存的寿命，因此按真实状态与资源判断。
- 根据 float/int 注解或 SDK 数组结果统一删除转换，能少写更多代码，但注解不会把 Decimal、数组标量或 dataclass 输入归一化，因此只裁剪实际生产者可证明的原生值。

## Consequences

缓存入口与其依赖可以直接追踪，数据记录和资源类也有明确区别。代价是旧 Python 类／singleton 名称退出，真实引用必须同批迁移；新来源或新的累计写入口需要重新核对生产者，不能沿用这些局部原生值结论。

完整读取本类别 11 个服务及九份完整 owner 差异，另外四个调用／既有测试文件仅做必要引用迁移，不扩张完整审核数量。Ruff、格式、Python 3.11 AST、限定的源码表面及显式调用绑定通过；静态证据不证明运行时等价。本次不执行应用、SDK、模型、数据库、回调、业务正则或 Python 测试。

按缓存类／singleton、图片索引、MinerU 与爬虫运行记录检索活跃笔记，没有同一所有者的既有决定需要吸收。换行修复保持独立记录并互链，不归档或改写其理由。
