# Agent Note: 诊断与回放脚本的共同规则和内部记录

Status: implemented

## Problem

采集与回放脚本重复维护相同的 JSON 读取、请求头和 case bundle 归一化。部分报告对本地生成的计数与完整统计字典重复兜底；证据胶囊在每一层完成字典选择后，又重复检查刚选择的变量。实际文件流和容器返回类型也没有说明清楚。

## Decision

回放入口直接导入采集入口现有的 `_load_json`、`_headers` 和 `coerce_case_bundle`。三份原实现的完整参数、默认、异常和函数体相同，仅 case helper 的说明文字有差别。回放在导入前明确加入自身仓库根路径，与现有独立 CLI 入口采用同一启动形式，支持脚本和模块两种入口；新导入模块没有执行探针的顶层调用，不新增公共工具模块或转发函数。

case loader 的所有成功路径都生成字符串 dataset ID 和字典列表，采集循环与回放 lookup 直接使用。文件文本流迭代已经产生字符串，行处理直接 strip。长度、比较、计数器以及 monotonic 差值直接进入原报告；原始 JSON、HTTP 响应、选项、错误、PII 脱敏与输出字段保持。

检索债务报告的五种内部统计记录在每个返回分支构造所需整数字段，摘要和行动队列直接读取。UTC 使用 Python 3.11 的同一时区对象。源码扫描的现有表达式和启发式保持，不执行扫描器或业务正则来验证。

胶囊的每个原始字段仍先选择 dict 或空 dict；之后只退出同一变量的重复类型探测，保留 proof 复制、must-recall 回退、签名和 hash 验证。证据包的字典列表 helper 说明实际 list 返回值，下游继续使用这份已复制的列表和字典；原始字段转换、证据去重、稳定 ID、quote 上限和错误文本保持。

incident 的每个 `_fetch_json` 返回都是非空字典，body 适配器只处理其字段，不再猜测传入的记录缺失。没有请求 body 的失败记录仍产生原 `_raw: None`。两个不需要调整的完整 CLI 保留原字节，继续持有持久化校验与有界 index replay 的真实边界。

## Alternatives considered

另建公共 CLI 模块可以承接更多重复 helper，但目前两个真实消费者复用已有入口即可。其他同名 case 函数还承担不同模式与转换，必须在各自完整类别核对后再处理。

把所有 dict／数字注解都当作已验证值会缩短更多代码，但 JSON、HTTP、回调和文件仍提供原始内容，因此只退出本地构造者已经保证的分支和转换。

## Consequences

同一采集和回放规则只维护一份，内部统计与外部输入的界限更明确。CLI 参数、help／默认、输出格式、状态与退出码、请求顺序、鉴权头、PII 策略、证据与配置指纹、事务、资源和失败路径保持。脚本路径的显式初始化需要在以后移动文件时一并维护。

活跃笔记按具体脚本、helper 和回放名称检索未发现同一决定；平台的回放 capture schema 与报告服务仍保留原所有者。本篇不替代它们的 wire 合同。

验证使用十二个完整原始文件、全部 diff、限定转换后的完整模块 AST、真实生产者与调用方、Ruff 和笔记门禁。不新增、修改或执行 Python 测试，不执行 CLI／--help、HTTP、数据库、应用、SDK、模型、数据、正则、回调或报告生成器；静态验证不表示运营回放与网络流程已经运行通过。
