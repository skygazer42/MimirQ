# Agent Note: 治理与运维组件直接消费已有所有者

Status: implemented

## Problem

治理、诊断、用量及运维界面仍经总入口读取业务 API 和 DTO，阅读组件时难以确认真实定义。部分公开组件把完整输入结构写在函数参数中，两个编辑组件又共用无业务名的 Props。诊断页维护两份字段和值完全相同的颜色表；重复内容治理的文件导入和模板导入各自重复维护同一段脚本合并。

行业规则的载荷构建器先生成 markers 数组和已经裁剪的 name，再对这些内部结果执行数组探测或相同的文本转换。返回类型又把确定的字段拓宽为未知字典，掩盖了本地生产者已保证的结构。

## Decision

组件从已有业务 API 模块和 DTO 模块导入原符号，保留原本的局部名称。两处原有网络替身同步模块路径，访问管理缓存测试为原 factory 增加 access 模块别名，原断言、输入和用例保持。该缓存测试直接挂载 GroupChipsInput，别名保证新的直接导入继续使用既有受控 API。共享 API、DTO、传输层和总入口继续由原模块拥有，本批不建立新适配层。命名组件输入类型使用对应组件名，函数仍使用原 Readonly 结构；框架默认导出、动态导入和组件寿命保持。

诊断页使用一份私有颜色表。两个消费者仅按键读取相同的字符串，没有暴露或修改表对象。MainMetricCard 的 tone 使用既有 MetricTone 的四值子集，三个实际生产函数使用相同的精确返回类型，移除重复断言，原颜色回退及所有调用值保持。

重复内容治理在原组件文件内使用 mergeProcessingScripts。两条流程仍在原时点读取配置、读取文件或构造模板草案，再按 language:name 合并：先记录已有脚本，后用新草案覆盖同键条目，保留 Map 的首次插入顺序。十条上限、disabled 默认、时间戳、stage、描述、原文以及随后写入顺序保持。脚本内容仅作为文本存储，不执行。

行业规则构建器保留其推导出的具体字段结构，只取消同一 map 之后对 markers 数组的再次检查，以及对已 trim 的 name 的再次 trim。后端返回的字典、数组别名和用户文本仍经过原始边界处理。

## Alternatives considered

- 运维面板的 Field 和 ActionButton 形式相似，抽成公共组件可以减少行数。但各面板的样式、参数和操作反馈不同，当前没有稳定的共同业务职责，因此各自保留。
- 复用 primitive-text 可以减少诊断页的标量函数。该函数接受 symbol，而诊断函数明确忽略 symbol，两者的输入规则不同，因此不合并。
- 用 ParserBackendStatus 替代本地 health 投影可以少一个类型。但现有 DTO 没有 health 字段，不能靠类型声明删掉真实版本信息检查，因此保留该投影。
- 为所有异步流程增加请求锁和访问管理可以覆盖更多竞态。但这会改变未修改的业务策略，超出本次风格整理，因此本批保留原异步流程。

## Consequences

调用方可以直接定位符号的定义，公开输入结构有明确名称，两处真实重复只维护一份。没有新增公共模块、Hook、Context、manager、配置开关、重试或兜底。文件输入、权限、认证、查询 key、缓存完成职责、操作范围、忙碌范围、DOM、文案、class、排序与预算保持。

ModelConfigDialog 与原测试的两个模块路径调整独立交付。用户 E 工作区中的同名文件只记录哈希和属性，不读取、覆盖或提交其内容；主整理可独立整合。

活跃笔记按组件名与实际机制检索，仅命中[设置父页面归属](../bug-fix/2026-11-05-settings-parent-state-ownership.md)和[访问管理缓存寿命](../bug-fix/2026-11-05-access-admin-cache-lifetime.md)。两者是部分关联的消费者边界，原决定继续成立；本篇只改变导入和局部代码表达，不吸收其请求、缓存或草稿规则。没有同一决定需要拒绝、删除或归档。

验证使用固定原字节、TypeScript 符号归属、全模块运行时投影、原有受控 DOM／源码测试及静态门禁，详细命令和结果保存在本类别证据目录。不运行浏览器、服务、Python、后端 SDK、数据库或真实网络，不据此宣称视觉或后台事务已经验证。
