# Agent Note: URL 入口错误收敛到实际处理需求

Status: implemented

## Problem

URL 校验为缺省网址、协议、主机和端口分别维护专用 HTTP 文案，解析步骤还重复包装 ValueError。系统 getaddrinfo 返回的地址已经有标准库契约，代码仍为不符合该契约的返回值定制 HTTP 400。用户明确要求削减没有实际区分或恢复需求的异常分支，原有分支本身不足以证明需要保留。

DNS 与传输错误还在底层转换成 HTTP 错误，下载的两个异常分支重复执行同一清理。配置来源已经明确，但每次下载仍校验数值、回填超时；响应声明长度也维护了与实际写入上限并行的一套解析和拒绝逻辑。

## Decision

普通 URL 格式错误在同一入口统一为 HTTP 400、detail 为 Invalid URL，解析器与主机／协议／端口不再各自定义用户提示。禁止 URL 凭据、访问范围、配额、重定向与资源清理继续表达各自实际契约。模型 API 地址校验同步使用统一格式提示，仍为 HTTP 400。

系统解析与传输异常直接传播到现有统一异常入口，不在 URL 工具中分别转换为 HTTP 400／500。下载器只在 BaseException 边界清理并重新抛出，包含取消；响应、客户端与文件仍在原作用域关闭。空系统结果在取首地址时失败，建立请求之前中止，不补默认地址。字面 IP 与域名的识别属于正常分流，保留其必要转换。

大小与超时约束由 Settings 的 Field 在加载时负责：字节数非负，超时有限且大于零。MAX_FILE_SIZE 已有正数约束，下载唯一调用方保留全局零字节配置选择 MAX_FILE_SIZE 的原政策；超时直接读取已验证配置，不再把零值回填为 30 秒。下载函数不重复检查同一来源数值。

大小上限统一由实际保存的解码字节计数实施，每块写入前检查 413。删除 Content-Length 提前解析和拒绝，这个头不再单独触发应用级超限错误；HTTPX／h11 仍负责传输协议有效性，不承诺与声明长度不符的响应能够成功。该上限不表示网络接收量或解码内存峰值上限。

个人 Python Skill 的 ERR-002 明确专用异常需要调用方区分或恢复需求，同一边界的普通格式错误可以统一转换，未处理职责的意外异常向上传播。频率用于安排处理优先级，输入、权限和数据完整性仍按真实契约判断。

本决定部分更新[API 工具所有者](../simplification/2026-11-11-api-utils-owners.md)的 URL 错误文案和系统返回值转换政策；其中目标传递、跳转、资源及其他工具职责保持。

## Alternatives considered

- 保留每种格式的专用文案能提供更细提示，但现有调用方只需要拒绝无效地址，模型测试还维护一套重复翻译；当前采用统一格式错误。
- 让全部无效 URL 直接抛原异常能进一步减少包装，但外部请求模型的 url 目前只有 str 与长度约束，基本合法性仍需要入口负责，不能把普通无效输入作为内部失败。
- 对不符合标准库返回契约的地址继续转换为 HTTP 400 能保持旧的异常注入预期，但没有真实用户输入或恢复责任支持这层包装，当前让错误保持可见。
- 将 DNS 和传输故障转换为专用请求文案，能提供更多特定提示，但当前调用方没有恢复动作，应用已有统一异常入口；工具只持有必要清理，不维护另一套故障分类。
- Content-Length 提前拒绝可减少声明大文件的读取量，但它是远端声明，文件字节上限已经在实际写入处完整实施。当前保留一个实际文件限额，传输协议错误继续由底层负责。

## Consequences

普通无效 URL 的 HTTP 状态保持 400，detail 有意合并为 Invalid URL；模型 API 测试对应为 api_base must be a valid HTTP(S) URL。依赖旧细分文案的内部测试需要后续迁移。

异常系统地址走原 ValueError，DNS OSError 或无系统结果不再自定义为 HTTP 400，原生异常由全局入口给出统一 500。传输仍失败并清理，500 响应使用统一格式；危险目标拒绝、凭据、重定向和实际字节上限保持。没有根据频率删除权限或输入合法性约束，没有新增默认成功、备用地址或错误吞没。

负字节配置、零／负数／非有限超时现在在加载配置时失败，不再等到业务执行时校验或回填。固定当前配置的有效值保持，非法配置的失败时点有意提前。调用方的内部类型契约需要随生产代码维护，不能把直接篡改 Settings 或旧补丁测试当作新的可空兼容模式。
