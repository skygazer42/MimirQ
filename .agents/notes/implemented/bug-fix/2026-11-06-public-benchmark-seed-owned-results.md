# Agent Note: 公共基准种子脚本使用实际查询行和切块缓冲区

Status: implemented

## Problem

CFEVER 与 MIRACL 的覆盖清理和引用校验各有一个已知单列 ORM 查询。原消费者只识别 Python tuple，真实 SQLAlchemy Row 会被清理路径跳过，或被引用校验当成 UUID 字符串转换，导致漏删向量或误报引用缺失。MIRACL 还通过 `(state.chunks or []).append(...)` 追加切块；真实缓冲区初始为空，追加落在临时列表上，后续分片始终没有切块可写。

## Decision

四个单列查询消费者直接解包一列。清理继续保留 UUID 筛选；引用校验继续保留 None 判断、UUID 转换及其错误处理。查询、租户和数据集过滤、批量范围、删除顺序、事务、向量删除的既有 best-effort 政策和会话关闭保持。

MIRACL 直接向 `state.chunks` 追加。该状态只由本流程构造，`__post_init__` 把默认 None 设为空列表，flush 后也重置为空列表；不增加空值兜底、不改变构造函数或引入另一份缓冲区。分片大小、确定性采样、计数、指纹、索引参数与提交顺序保持。

这五处行为变化使用独立修复提交。后续纯风格比较只对这两个脚本采用修复后的完整快照，原始基线和先前阶段证据保留。

## Verification

固定提交的两个完整模块经精确 AST 投影，只允许两处单列表达式、两处循环解包及首条重复赋值退出、一个 append 接收者改变。已有 SQLAlchemy Query/Row 源码确认单列结果的可迭代行契约。标准库字面量列表和单列元组控制只说明列表归属与解包规则，不代表执行了真实 SQL、种子数据或目标函数。

现有 MIRACL 测试覆盖 dry-run 计划，并在主流程的执行分支注入种子结果和引用校验结果，没有发现固定这五处错误的断言；所有 Python 测试保留原字节。本轮只运行隔离标准库源码 AST、哈希、JSON、原生字面量控制、Ruff 和笔记门禁，不运行应用、SDK、数据库、业务数据、目标脚本、抽取的业务函数或 Python 测试。

## Alternatives considered

- 额外识别 tuple 与 Row 可以覆盖两种表现，但查询列数已经确定，直接解包同时适用于两者，避免引入新的类型分支。
- 更改 `_ShardBuffer` 的构造字段或在 append 前补空值分支可以重新分配缓冲区，但现有构造和重置已建立列表归属；直接追加保持原状态和资源生命周期。

## Consequences

覆盖清理可取得实际文档 UUID，引用校验可取得实际切块 UUID；MIRACL 的首个切块会进入真实分片缓冲区。运行时数据库、向量存储与完整种子链仍需后续环境验证，静态证据不宣称这些集成已通过。

活跃笔记检索命中[周期审计单列查询](2026-11-05-periodic-audit-single-column-rows.md)和[定时任务单列查询](2026-11-05-scheduled-job-single-column-rows.md)，两篇持有不同所有者并保留；没有同一公共基准脚本的决定需要吸收或归档。
