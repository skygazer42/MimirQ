# Agent Note: 证据修复保留预算外的引用尾部

Status: implemented

## Problem

证据条目允许多条 reference_sources，修复请求也允许把 max_refs_per_item 设为 1。服务只扫描这个前缀，却在 apply=true 且前缀至少一条引用成功重连时，用 patched_refs 覆盖整个原始引用列表。未进入预算的尾部因此被删除。dry-run 或没有实际改动的条目不走写入分支。

## Decision

既有 apply 且 changed 分支调用持久化所有者时，传入修复后的前缀加原始列表从 len(refs) 开始的未扫描尾部。只改变这一个保存参数表达式。尾部不扫描、不规范化、不去重，也不计入本次修复统计；它保持原顺序与原始值。

原始列表的 shape 检查、批准／归档策略、引用预取、扫描预算、报告与 changes 上限、ACL、逐项提交和审计失败政策继续留在原处。该真实缺陷修复与后续等价风格整理分开提交。

## Alternatives considered

- 取消引用扫描上限可以顺便修完全部引用，但会取消现有查询与处理预算，因此保留原有限前缀。
- 在持久化 helper 中重新读取或按 ID 合并旧列表，可以集中处理保存行为，却会扩大 helper 契约，并引入额外查询或新的去重／排序规则。当前调用方已经持有前缀和原列表，直接组合保存投影即可。

## Consequences

保存结果可以包含超过本次扫描预算的原有引用，但只有前缀参与修复与统计。这不会恢复此前已丢失的引用，也不重写未实际变化的条目。未来若需要存储裁剪，应定义独立政策，不能把扫描预算当成删除权限。

源码核对覆盖真实 create/patch 与 repair schema、写权限 API 和队列 job。完整模块 AST 只允许这一保存投影变化；Ruff、格式与 Python 3.11 语法检查通过。没有新增或运行 Python 测试，没有执行服务、数据库、回调或业务正则；静态证据不代表运行时回归。

活跃笔记按服务名、尾部和未扫描引用检索，没有同一决定需要吸收或归档。
