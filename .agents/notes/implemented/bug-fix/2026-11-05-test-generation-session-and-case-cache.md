# Agent Note: 测试问题生成的弹窗会话与用例缓存归属

Status: implemented

## Problem

测试问题生成请求仍在等待时，用户可以通过现有 Radix 关闭按钮退出，再从另一个文档重新打开弹窗，也可以通过“上一步”返回来源选择并改用对话。旧完成会把新弹窗或新的来源配置切到旧问题预览，旧错误会进入新表单，旧忙碌状态也会阻止或覆盖新一轮操作。

生成接口返回的 saved_case_ids 已经确认后端保存了用例，但弹窗和父级完成回调都没有刷新用例查询。仍挂载的 TestCaseManager 会继续展示原缓存。身份范围变化清除 QueryClient 时，旧生成响应也不能继续发布到同 key 重建后的范围。

## Decision

生成动作捕获实际来源查询的实体：文档来源使用已有文档列表 key，对话来源使用已有会话列表 key。完成时仍以 QueryCache 中的同一实体为归属；实体被移除后，不发布旧预览、错误、完成通知或缓存失效。这里沿用 QueryProvider 的清理边界，不读取 token，也不建立另一份身份状态。

弹窗当前请求另由组件内计数标识。关闭会话或通过“上一步”返回来源选择，使旧标识失效并释放当前弹窗的忙碌状态。返回来源选择保留已有选择与生成配置，允许用户继续选择并发起新请求。只有当前标识更新问题、错误和预览步骤；旧 finally 不能清掉新请求的忙碌状态。

普通关闭不撤销已经提交的后端生成与自动保存。来源查询仍存在时，已保存的完成结果会刷新用例查询并保留原完成反馈，同时不覆盖后来打开的弹窗。缓存失效前缀来自现有 regressionCases key 工厂的前两个字段，只作用于用例查询族；运行历史和其他评测查询不因此刷新。没有保存 ID 的预览保持原缓存。

## Alternatives considered

- 只比较数据集 ID，代码更少，但身份清理会移除后重建相同 key，参数相同不能证明原实体仍有效，所以使用实际查询实体。
- 给共享 key 增加身份或 generation，隔离直观，但会改变现有缓存契约并重复 QueryProvider 的身份边界，因此共享 key 保持原样。
- 关闭后完全忽略后台完成，容易防止旧预览，但会遗漏已经保存的真实用例和原完成反馈，因此区分当前弹窗与仍有效的查询归属。
- 失效全部 evaluations 查询，调用简单，但会多发无关运行历史请求，因此仅失效现有用例查询族。
- 关闭时取消或回滚生成，可以减少旧回调，但现有接口没有对应的取消或回滚协议，且自动保存可能已经完成，因此不改变后端任务。
- 生成时禁用“上一步”，能够阻止来源改变，但会取消现有可回退流程，因此在返回来源选择的动作中退休旧请求标识，保留导航与配置。

## Consequences

原文档、对话请求字段、自动保存参数、数据选择预算、错误文案与弹窗 DOM 保持。后台写入不会回滚；来源查询被移除后，旧完成只释放仍属于它的本地忙碌状态，不把生成内容带入新范围。

实现依赖来源列表仍由同一 QueryClient 管理，以及回归用例 key 的前两个字段标识查询族。若来源加载改成无查询路径或 key 布局变化，需要同步生成动作归属和失效范围。

真实 Dialog、TestCaseManager、QueryProvider 与受控 API 的 10 个 DOM 用例覆盖关闭重开、旧完成与错误、并发忙碌状态、自动保存刷新、仅预览、对话请求和真实身份清理事件。原字节测试在原生产源码上为 7 失败、3 控制通过，修复后 10 个通过。数值差异的另一组 7 个用例独立验证缺失与零值的区别。

补充回归通过实际“上一步 → 从对话生成 → 选择对话 → 下一步”操作证明旧文档完成不会覆盖当前配置。该用例在补充修复前断言失败，同字节用例在修复后通过，生成模块原有 10 例也继续通过；原案例与既有 RED/GREEN 证据保留。
