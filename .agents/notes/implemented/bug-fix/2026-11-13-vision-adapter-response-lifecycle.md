# Agent Note: 视觉适配器保持响应失败可见并释放资源

Status: implemented

## Problem

集成分块的 LLMBundle 持有真实配置和每实例 requests.Session。响应解析原来把缺少必需字段或非文本内容变成空文本，调用方无法区分合法空内容和损坏响应；取得的 HTTP 响应与连接池也缺少明确的释放入口。固定上游消费者不提供 close 调用点。

## Decision

LLMBundle 保留为有状态客户端，直接读取已经声明和校验的 Settings 字段。视觉配置为空时借用通用 API key／base 是实际配置约定，继续保留；模型覆盖、请求载荷、超时、token 和温度设置不变，每实例连接池与 cookie 状态继续复用。

请求响应使用自身上下文管理器，HTTP错误、JSON错误及协议错误均退出响应作用域。只有原来的200状态成功，原错误前缀和截断日志保持。响应必须是对象，choices、首项 message 和 content 是必需字段；缺键或不符合结构直接失败，非文本 content 抛 TypeError。真正的 content=None 仍按原约定表示空文本。

显式 close 使用同一个幂等 finalizer；finalizer 的回调只持有 Session，不持有 LLMBundle。固定上游没有关闭钩子时，正常回收或解释器退出仍可释放连接池；显式关闭后禁止继续请求。不引入共享全局客户端、逐请求新 Session、重试或备用模型。

未配置视觉能力仍抛原 NotImplementedError，由已有上游可选视觉分支承担其明确定义的降级。坏响应不再伪装成空成功，最终由原调用方的错误边界处理。[集成分块实际所有者](../architecture/2026-11-13-integrated-pipeline-canonical-owner.md)说明固定上游和本地适配的不同维护责任。

## Alternatives considered

- 每次请求新建并关闭 Session 可以简化释放，但会取消原有连接池复用和每实例 cookie 状态，因此保留实例生命周期。
- 只新增 close 方法可以明确资源所有者，但固定上游不调用它；采用不保留 self 的 finalizer 补足真实调用约束。
- 将损坏响应继续转为空文本可以让可选视觉链继续走，但会隐藏协议错误；只保留真实空 content 的空文本语义。

## Consequences

成功载荷、模型选择和池复用保持，坏响应及关闭后调用明确失败。新增的响应对象／文本检查属于实际外部协议边界，关闭状态检查属于真实资源生命周期；没有推测性配置兜底、兼容层或重试。

20项有限假 HTTP／Session／配置、弱引用和回收协议核对覆盖响应释放、池复用、显式关闭与正常回收；另外做独立源码复核、静态检查与应用装配检查。没有真实 HTTP、模型请求或应用测试，不证明供应商响应兼容性、真实连接池行为或强制终止时的清理。finalizer 不能代替业务可控情况下的显式关闭，也不保证强制退出时执行。
