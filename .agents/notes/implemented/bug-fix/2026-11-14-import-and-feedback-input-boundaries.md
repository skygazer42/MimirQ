# Agent Note: 导入数据的文件、引文、时间与反馈边界

Status: implemented

## Problem

导入解析器声明接受可空文件名，却直接 strip；CSV 多出的无表头值又成为 DictReader 的 None 键，随后字符串处理抛出异常。外部会话的引文允许任意嵌套 JSON，非文本内容也会在 strip 失败。合法无时区时间与导入器的 UTC 当前时间混合比较会触发 TypeError。

外部导入的消息也可能没有 request_id。反馈表允许空追踪引用，但服务仍对这个真实 None 切片，导致正常反馈失败。

## Decision

未提供文件名时明确抛出现有不支持格式的 ValueError，由既有 API 入口转换；不填空字符串或推断格式。CSV 溢出值在读取边界报告原零起始 index 格式的逐行错误，跳过该行，保留后续有效行及已接受条数上限。命名的未知列和缺失列值按原规则处理。

非文本引文不进入内部引用格式，完整原候选仍保存在来源 metadata；有效文本、UUID 和零分语义保持。无时区消息时间按导入器的 UTC 时钟解释，显式时区原样保留，再执行原来的顺序比较和一微秒递增。没有新增本机时区推断、时区配置、请求模型或状态码规则。

缺失追踪 ID 继续作为真实 None 传到可空字段，只对已有字符串执行长度截断。权限、事务、审计及提供方调用不因为这个可空值而降级或绕过。

## Alternatives considered

把无表头列丢掉或给它起一个临时名字会隐藏导入数据错误；按已有逐行错误协议处理。将任意引文内容 str 化会把不支持的数据伪装成有效引用，因此保留原始候选并跳过内部格式转换。拒绝所有无时区时间会收紧原先接受的输入，采用明确的 UTC 约定并保留显式时区。

## Consequences

损坏的行有可见错误，真正缺失的数据保留缺失语义；不再制造空追踪 ID、未知格式或额外 metadata 字段。无时区按 UTC 解释是明确的导入约定，不声称原请求 schema 已经强制该规则；没有执行历史数据迁移。

原始文件／CSV 两个失败和另三个可空／原始数据失败分别存证，修后以有限原生 CSV、datetime、UUID 与受控查询端口核对。可空文件名只按声明的 SDK 域验证，未重放真实 multipart／HTTP；没有运行数据库、模型、应用测试或真实导入任务。
