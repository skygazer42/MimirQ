# Agent Note: 文档 Hook 的查询归属与轮询生命周期

Status: implemented

## Problem

文档动作、上传和轮询原先都通过最新的列表 ref 写缓存。在数据集 A 发起删除、切到 B 后，A 的完成结果会减少 B 的总数；身份范围变化清除 QueryClient 后，旧上传还能把旧文档插入新建的同 key 查询。批量上传也会继续发出余下请求，并在结束时刷新后来选中的列表。

文档轮询的取消只清除定时器，没有使正在等待的 status 或完整文档响应失效。旧请求可以覆盖新一轮轮询、重新安排定时器。列表加载的旧错误也会覆盖新数据集的当前状态。

两个派生状态问题会让文档查询结果失真：相同初始参数被父组件重新构造时，会抹掉显式加载的查询条件；MiniSearch 在 effect 中重建索引，结果 memo 却已使用旧索引处理新文档，导致搜索结果停留在旧集合。

## Decision

本文关于文档显式读取及批量刷新复用新鲜缓存的策略由[前端显式刷新与请求结果归属](2026-11-12-frontend-request-results.md)部分替代；下文保留原取舍，查询实体与轮询生命周期仍有效。

React Query 继续持有文档列表。useDocumentList 在用户调用动作时捕获已有查询实体及其参数，生成文档专用操作对象。实体仍在缓存中时，后台动作可以更新原列表；实体被移除后，该操作不再发布结果或发起后续批次。查询参数与当前列表访问仍一致时，错误才进入当前视图。这个对象不保存另一份文档数据，也不读取 token 或另建身份状态；现有 QueryProvider 的身份变化清除缓存仍是边界。

已完成查询被 clear 移除时，原 observer 不会自行清空组件中的结果。列表通过 useSyncExternalStore 观察查询移除后的实体变化，使仍挂载的视图重新读取当前查询。placeholderData 只复用仍在缓存中的原实体；普通数据集切换保留已有快照，身份清理后的旧实体则不能继续显示。实体变化也清除原动作错误。

动作和上传在公开回调入口捕获操作，避免 mutation 开始前的异步间隔改变上传数据集。缓存实体失效时使用 React Query 的 CancelledError 拒绝完成，不把未继续执行的批量任务报告为成功。批量刷新只读取原查询，不重新选择它；现有 query key、缓存时间、文件分组、重试及并发上限保持。列表 GET 使用已有 API options 转发查询 signal。

删除的缓存投影只在本次实际移除文档 ID 时减少总数。服务器刷新已经移除该文档时，迟到的删除完成不再重复扣减。

每个文档的轮询拥有一个独立对象和最多一个定时器。取消、替换和卸载都会移除归属；status 与完整文档响应只写入仍有效的原查询，旧完成不能删除新轮询的资源。终态详情读取完成后才释放当前归属。查询实体失效后也不再安排后续请求。

初始参数只与上一组初始参数比较；显式加载参数继续作为当前查询参数。搜索索引随输入数据在 memo 中创建并填充，再用同一集合计算结果，保留字段数组相等时的复用与原搜索选项。

## Alternatives considered

- 只比较数据集 ID 或参数值，判断简单，能阻止部分跨列表写入；但同 key 的查询会在身份变化后重建，参数相同不代表结果仍属于当前身份，因此以 QueryClient 中的实际查询实体为准。
- 给所有查询 key 增加身份或 generation，可以把隔离放入 key；但这会改变现有缓存与调用契约，并重复已有身份清理边界，因此保留 key，只约束异步操作的缓存归属。
- 取消旧范围时完全放弃后台缓存更新，代码较少；但切换列表不代表原后台动作失效，返回 A 时仍应看到其完成结果，因此保留原查询仍存在时的更新，只在实体移除时取消。
- 继续在 effect 更新索引并额外保存搜索结果状态，可以触发重算；但会新增需要同步的派生状态。索引与数据一同构建后，结果直接由当前输入计算。

## Consequences

文档查询实体成为动作、上传和轮询的共同归属。内部 Hook 的操作参数已在 useDocuments 组合与测试中迁移；useDocuments 的公开参数、返回键和偏好字段保持。加载状态聚合、当前操作的错误、空上传结果、上传重试与并发策略仍按原契约呈现。

取消前已提交的后端写入不会回滚。现有 getStatus API 不接受 abort 参数；完整文档 get API 已支持第三个 request 参数中的 signal，本 Hook 仍沿用单参数调用，没有接入该 signal。因此旧 GET 可能仍完成，但不能再写缓存或继续轮询；列表 GET 使用现有 signal 取消。缓存过期与回收仍由原策略决定；批量刷新也继续遵守 fetchQuery 的新鲜度策略。

真实 Hook、QueryClient 与 MiniSearch 的用例覆盖原生产文件上的轮询、查询、动作、上传、搜索及无手动 rerender 的缓存清理回归，并保留当前路径控制用例。最终数量与命令记录在本批报告中。验证限定于现有 Vitest、前端类型与静态检查，没有运行服务或浏览器，也没有修改 auth/API auth、viewer 或 document-view store。

活跃笔记检索仅命中[共享查询 Hook 的异步结果归属](2026-11-04-shared-hook-request-ownership.md)，其决定覆盖身份 profile、索引修复和连接器，文档查询实体与搜索索引属于本记录的独立问题；该笔记不被替代。中央覆盖状态及独立集成审查仍由控制者维护。
