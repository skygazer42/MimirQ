# Agent Note: 表格导入与查询使用实际读取和资源边界

Status: implemented

## Problem

CSV 分隔符嗅探先读取整个文件再切片，实际读取量没有受参数限制。列名清洗只统计原始名称，输入 a、a_2、a 仍产生两个 a_2，不能满足 SQLite 的唯一列名要求。连接已经创建后，PRAGMA 初始化失败不会关闭它；安装查询超时处理器失败又被吞掉，查询会在没有所需超时策略的情况下继续。两处表格模型工厂又把配置的重试 0 次改成 2 次，与 SDK 明确的零值契约不符。

## Decision

嗅探通过文件上下文读取 max(1024, max_bytes) 个字节，保留原来的最小样本量与解析降级。名称计数同时登记已经生成的名称，发生碰撞时继续选择下一个后缀，保留原始列顺序和大小写归一化规则。

读写连接在初始化失败时先关闭，再传播错误；正常返回后仍由原调用方关闭。清理自身失败也保持可见，并保留原异常上下文。请求已经启用的超时处理器无法安装时终止查询，不降级为没有超时的执行；明确关闭超时的零值规则不变。SQLite 只读、表范围、租户文档路径、参数与响应预算保持。

已建立的 DataFrame、SQLite 结果和内部整数直接使用其实际契约；真实快照、持久 metadata、DOCX、空工作表和可选侧链输入继续在原边界处理。

共享模型工厂直接传递 LLM_MAX_RETRIES。原生 Settings 提供整数，OpenAI SDK 明确用 0 禁用重试，LangChain 只在 None 时省略该参数；本地无需再给整数补缺省。正的重试次数保持，零值现在禁用重试，没有新增重试或模型调用策略。

## Alternatives considered

读取后再截断能复用旧实现，但不能限制文件读取的内存占用。只给重复原始列名加计数会遗漏原始名称与生成名称的碰撞。保留超时安装的日志后继续执行看似可以降级，却使已启用的预算失效，因此选择明确失败。

## Consequences

正常查询和导入仍使用原路径、SQL、限制及结果；只在确定的名称碰撞和失败路径上改变行为。损坏的内部 DataFrame 状态不再被合成空表或空样本。CSV 嗅探读取失败仍属于非关键估计失败，表格重置与逐工作表侧链的既有降级没有借此统一修改。

11 个原／现选源代表复现读取量、名称碰撞、连接初始化与超时失败。其他小型原／现观察核对真实调用链的查询、诊断、模型参数与消息，9 个路由代表保留 chartsheet／工作表缺失维度和关闭策略。重试零值另存原来的六个工厂参数观察和修后三个观察，并读取已安装 SDK 的声明，未执行 SDK。只使用数据与受控端口，没有运行真实 pandas、SQLite、文件、模型、网络或应用测试；不据此宣称生产集成通过。
