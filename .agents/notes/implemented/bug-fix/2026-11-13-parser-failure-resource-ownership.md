# Agent Note: 解析失败仍由取得资源的一层收尾

Status: implemented

## Problem

子进程日志超限会抛出错误，原入口只为取消终止 worker，错误离开后可能留下活进程。grace wait 的未知异常被当作已退出，跳过后续 KILL。另有图片转换副本未关闭、文件 stat 失败被视为零字节，以及显式无效 KG 模板 UUID 被静默当作未配置。

## Decision

runner 的失败收尾覆盖日志超限等异常路径，按原终止／等待／升级协议尝试回收取得的活进程。等待的未知错误不证明进程已经退出，继续原升级路径；原超时、进程组、取消、主异常及临时文件清理合同保留。

worker 和预览助手关闭自己打开的图片及 convert 副本，借用 raw 图像继续由原拥有者处理。预览读取按既有大小预算限量读取，避免文件在 stat 后增长时直接全读。Root 图像 stat 失败沿可选资源错误边界记录并跳过，不伪造 size=0，也不据未确认大小删除文件；正常禁用上限和已知超限的原行为保持。

KG 模板 ID 的空字符串仍表示没有覆盖。显式无效 UUID 向已有 KG channel 错误入口传播，不改用另一模板作成功结果；原有效 UUID、任务指纹和模型预算保持。问题计数只把标准数值转换失败按原 3..5 约束处理，意外数值协议错误继续可见。

这些边界与[流程函数所有者](../architecture/2026-11-13-document-pipeline-function-owners.md)配合，不新增重试、另一份状态或新配置。真实 NULL／缺失状态继续保留，原始 metadata 与 SDK 数据仍在实际边界校验。

## Alternatives considered

- 只在取消时停止 worker 可以保原路径，但日志超限是已复现的另一退出点，同样持有活进程。
- 将 wait 异常或 stat 异常视作成功退出／空文件能继续主流程，却没有建立所需资源状态，因此保留失败可见性并走原收尾入口。
- 关闭所有传入图像能缩短所有权判断，但会抢先关闭借用资源，因此只补自己取得的句柄与副本。

## Consequences

有限假进程、Path 与图像端口复现原缺口并核对终止／升级、主异常、取消和关闭顺序；类型值与 API 模型验证使用真实轻量数据模型。操作系统子树终止、真实 SDK、图片／编码质量及磁盘并发没有运行验证，不能由 fake 结果推出这些环境保证。Python 应用测试保持原字节且未运行。
