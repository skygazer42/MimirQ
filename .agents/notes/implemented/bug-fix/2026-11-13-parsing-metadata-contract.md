# Agent Note: 解析元素与时长的恢复合同

Status: implemented

## Problem

metadata 恢复只检查元素是否为对象，空对象和数组也会被承诺为 ParsingElement。本地文件恢复却已经检查全部元素字段，两条入口对同一前端元素类型有不同接受范围。

手动恢复正文时，远端解析器与时长会更新共享文档库，随后构造的 run 和队列却继续使用请求前值。被动选择文档又把 null、空串或 false 转成 0；字段缺失时仍携带 durationSec: undefined，覆盖原有时长。真实 Hook 分别复现了错误元素、旧元数据和缺失值覆盖。

预览组件的目录名、路径、徽标、关闭回调只存在于 Props，没有被读取或显示。徽标函数及 Shell 的四项计算只服务这条无效传参链。测试还保留已经不属于正式 Hook options 的原始辅助函数注入和旧 barrel mock。

## Decision

lib/parsing-elements 持有原 Store 的完整元素校验和可选 metadata 元素读取。两个恢复 Hook 和 Store 直接消费同一纯校验，不从 Store 导出校验门面，也不运行 API 客户端。metadata 继续过滤坏条目，Store 继续拒绝带坏元素的文件；缺失或非数组的可选元素集合仍按原读取政策视为没有元素。这个政策不处理或掩盖 HTTP 请求失败。

校验覆盖公开类型的必需和可选字段，保留 0、空文本、null、字段省略和有限小数坐标。当前 HTTP schema 的页号与坐标要求整数，但前端 metadata/存储的既有数值合同更宽，不能直接替换。类型检查不额外发明正数、非空身份或坐标顺序限制。

parsing-page-utils 继续持有解析工作台实际复用的纯计算，时长读取只接收有限数字或已经支持的非空数字字符串；其余输入保持缺失。两个目录映射及手动恢复保留既有时长，被动更新省略缺失字段，真实 0 仍写入。已校验解析 API 响应直接消费数字/可空字段，不重复强转。最终恢复的解析器、标签和秒数同时供共享库、run 与队列使用。

无效预览 Props、仅供其使用的计算、徽标类型和函数全部退出；没有移除已经显示的状态或关闭动作。辅助函数移除不适用的 client 指令和重复字符串转换，测试退出过时固定函数注入与 barrel mock。实际页面和 Hook 继续直接依赖既有函数，不新增管理器、Context、版本计数或依赖。

## Related decisions

本篇接管[解析工作台固定值与类型归属](../simplification/2026-11-05-parsing-workspace-owned-values.md)中“元素只筛空值与非对象”的决定。其固定函数直接依赖、类型归属、配置提升理由继续成立，原始冻结基线重放保留为当时验证事实。[浏览器 Store 恢复](2026-11-12-browser-store-restoration.md)的坏条目政策和字段恢复仍适用，本篇共享其元素合同。[文档库同步](2026-11-13-document-library-reconciliation.md)的来源和请求起点归属继续成立，时长读取及元素谓词由本篇进一步核验。

活跃笔记检索命中上述部分重叠记录，以及解析阶段函数归属的结构说明；后者没有持有相反的数据校验决定。没有同一问题的独立待落地提案需要拒绝或归档。

## Alternatives considered

- 直接复用 HTTP 的 Zod 元素 schema，可以减少形状声明。但其整数页号/坐标比原 Store 合同窄，还会让纯存储校验运行接口模块，因此复用已有 Store 检查并放入纯模块，不改变 HTTP 合同。
- 把原校验直接从 Store 导出，迁移最少。但规则本身没有 Store 状态或副作用，两个不同读取入口都需要它，所以 Store 作为消费者而不是校验所有者。
- 只修手动恢复的最终变量，可以消除库与队列的明显差异。但独立复核和真实 Hook 回归确认被动入口仍制造 0、覆盖旧值，因此共享实际时长读取规则，并按部分更新合同省略缺失字段。

## Consequences

未知对象不再假装是元素，合法旧格式和字段值保留；库、历史和队列一致，缺失时长不再伪造 0。元素规则增加一个有实际复用的纯模块，metadata 与 HTTP 的不同接受范围仍需分别维护。时长字段省略是更新语义，条件对象展开中的空对象不表示请求成功或降级成功。

修改前分别有 2 项元素、5 项恢复元数据、6 项被动时长回归失败；当前三个相关文件 59 项通过。完整前端 verify 的 195 文件、1,379 项用例与 lint、UI、类型、API 检查通过；格式与逐项名称/写法绑定另有核对。独立复核提出的三项问题均已修正并定向复查。没有启动浏览器或服务，HTTP/缓存端口为受控替身，不声明真实服务、PDF SDK、布局或内存模式保存耐久性已验证。

三个小文件完成全文审查，其余大型消费者只批准本篇所列范围。治理保存反馈由[本地文档保存确认](2026-11-13-browser-document-save.md)继续修正；解析正文读取、空值和远端任务消费由[解析正文恢复](2026-11-13-parsing-content-restoration.md)接管，其余未核验的库写入及整个前端剩余内容继续在完整目标内，证据记录位于 .frontend-structure/20261112-full-frontend-guidelines/element-contract/。
