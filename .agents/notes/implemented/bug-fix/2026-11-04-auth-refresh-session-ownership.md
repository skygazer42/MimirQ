# Agent Note: OIDC 刷新结果的会话归属

Status: implemented

## Problem

API 客户端在处理 401 时读取当前 token，等待 OIDC 刷新后直接写回凭证或清空会话。用户在等待期间登出或登录另一账号时，旧刷新会覆盖新登录或使其退出。登出后使用相同账号和 token 重新登录时，仅比较 token 与缓存范围也不能区分两次会话。全局刷新 promise 还可能让新账号加入旧账号的刷新请求。

## Decision

`auth-storage` 持有一个内存中的会话版本。显式登录、清空会话和有效的身份范围通知使旧版本失效；普通 `setAccessToken` 刷新不替换会话。版本没有持久化格式或精确增量契约，原有缓存 key、存储 key 和事件触发规则保持。

Axios 在准备原始请求时保存版本和缓存范围，重试保留原归属。401 处理在刷新前及等待后核对该归属、实际请求凭证和当前 token，再决定是否写 token、重试或清空。流式 `authenticatedFetch` 在原请求前保存相同边界。已失效的请求继续返回原 401／错误；取消的请求沿 Axios／AbortSignal 既有取消契约失败。

OIDC 刷新和现有流式刷新合并记录使用会话版本、范围和 token。新会话建立自己的刷新请求；旧请求完成只释放它仍持有的 promise。同一会话的并发调用继续共用刷新。单个调用方取消只撤销自己的后续行为，不取消共享刷新或其他调用方。

`useAuth` 在 profile 查询开始时保存同一版本，并在成功写回和错误处理前核对。原有查询取消、当前 token 匹配、401／500 分支和缓存 key 不变。同范围的显式登录仍按原规则保持事件静默；旧 profile 查询不能因未被 QueryProvider 取消而覆盖或清空新会话。仅轮换 token 的合法 OIDC 刷新不改变会话版本，仍可保存当前 profile。

## Alternatives considered

- 只在等待后比较 token，可拦住不同 token 的新登录，但无法识别相同 token 的登出／重登。缓存范围也会复用，所以在实际认证存储所有者中增加会话版本。
- 仅保护客户端的写回，可以保留全局 promise，但新会话仍可能收到旧账号的刷新结果，因此刷新合并本身也按同一边界隔离。
- 把调用方的 AbortSignal 传给共享刷新，能提前结束它的等待，但会取消同一会话其他调用方需要的刷新。保留共享请求，仅停止取消调用方的写回和重试。
- 强制每次同范围登录都发出身份范围事件，可以让 QueryProvider 清空旧查询，但会改变现有缓存与通知策略。在实际写 profile 的 Hook 核对版本，可保留静默策略及已审核的取消／token 判断。

## Consequences

原有正常刷新、只重试一次、当前会话 401 清空、500 失败、SCIM 显式凭证、匿名及遥测不登出规则保持。新增状态只在当前页面运行时存在；不改变后端会话、cookie、API 或缓存格式，也不撤回已发出的网络请求。

回归用例使用真实拦截器、认证存储和 OIDC 解析器，仅替换 HTTP adapter／fetch 边界。延迟刷新后的换账号、登出、相同凭证重登、旧请求 401、跨账号刷新合并和取消在原代码上失败；正常并发刷新和错误契约仍通过。未启动浏览器、应用服务或 Python 测试，真实身份提供方和跨标签端到端行为尚未验证。

组合回归还使用真实 QueryProvider、useAuth、authApi 与存储，复现同账号同 token 重新登录后的旧 profile 成功、401 和 500 响应；对照用例保留同一查询中的合法 OIDC 轮换。它们在已有下层修复但尚无 Hook 版本检查时出现三个失败和一个通过，补齐检查后全部通过。
