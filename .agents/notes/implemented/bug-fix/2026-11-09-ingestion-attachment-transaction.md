# Agent Note: 入库附件与进度统计共用真实事务结果

Status: implemented

## Problem

入库追踪的 flush 遇到非重复 IntegrityError 后回滚，却返回 True，上层随后继续增加文档数量并提交没有对应附件的统计。查附件失败还被转换成不存在；统计 helper 自行吞错，可能把部分状态与新附件一起提交。

收尾统计存在同类局部吞错，状态更新则把同一事务拆成四份相同捕获；空锁结果的安静 commit 会绕开 required 失败策略。criticality 对未知值一律选择 best_effort，内部错误可能无声降低要求。

处理器的显式要求覆盖也可能是未知字符串，外围按“不是 required”吞掉服务校验错误。数值和元数据 UUID 的解析还捕获所有 Exception，使实际解析错误与意外执行错误混在一起。

## Decision

add_document 持有同一个事务：按原租户／run 锁定、查询附件、插入并 flush、更新统计、commit。只有整组成功后才发布结束指标。附件查询／flush／commit 的三份单次转发退出，统计函数保留独立业务职责但直接传播错误。

已存在附件仍沿原 commit 释放事务，已知唯一约束冲突按原幂等 no-op 处理。其他失败记录租户／run／文档 ID 与异常类型，再 rollback 并结束该项可选追踪，不继续统计或补造记录；rollback 失败不伪装恢复。上传主文档的既有结果不由本追踪结果改写。

真实缺失 run 仍返回，附件构造、source_ref 上限、状态规则、统计字段／阈值、元数据解析和结束指标入口保持；没有新事务类、状态包装、重试、补偿写入或默认身份。

close_intake 沿同一事务整理，收尾统计直接传播到该 owner，只有整体 commit 成功才观察结束指标。状态更新的四段 SQL／统计按原顺序进入一个失败边界，warning 后 rollback；required 直接重抛，best_effort 保留可选返回。未知 criticality 在查询前失败，合法值的原大小写／空白归一化保持。

空锁结果的事务结束直接 commit，错误交给现有状态 owner，不再隐藏 required 失败。四份无独立业务政策的 commit／rollback／锁／错误转发退出，回滚失败直接传播；所有租户、锁顺序、进度算法、阈值、实际空结果与查询参数保持。

处理器在应用文档字段前验证规范化后的显式要求；合法默认推导、取消检查、required 门和主提交顺序保持。可选通知的外围故障以租户／文档和异常类型 warning，不打印原始异常。原始 JSON 数字解析只处理 TypeError／ValueError／OverflowError，UUID 只处理 ValueError；预期坏值仍沿原返回，意外错误不再补成零或缺失 ID。

## Alternatives considered

- 只把 flush 分支改为 False 能挡住一个错误，但附件查询与统计的局部吞错仍可能继续写入不完整状态。
- 将可选追踪的任意失败抛给主上传可以直接报错，但主文档此前已经由原 owner 提交，容易误报成功文档为失败；保留追踪边界并使其事务与日志明确。
- 为每步增加 success／error 对象可以显式传状态，但会保留多层转发与新协议；现有异常和一个事务入口即可表达。

## Consequences

附件与其统计按同一数据库结果推进，不再在失败 flush 后伪报数量。可选追踪仍可能缺失，需要运维从标识与类型日志定位；预期重复不重复累计。未知 commit 结果不盲目重试或删除主文档，后续按原查询／重整规则核对。

需要持久化的状态更新不能再因局部 commit 捕获或错拼要求而被忽略。统计准备失败不提交部分 config／终态；回滚失败不继续假称 Session 可用。可选指标仍由原非关键入口持有，不把指标问题改成主文档失败。

对照真实唯一约束、三个上传调用者、主文档提交位置和完整服务快照；工作树／暂存模块 AST 分开限制本批事务改动，其他草稿保留原归属。限定 Ruff／格式、Python 3.11 AST／源码编译及 Note 门禁提供静态证据。按用户要求未新增、修改或运行 Python 测试，未执行上传、附件／统计函数、SQL／事务、Session 或指标，静态检查不证明真实并发与故障恢复。

收尾／状态增量完整模块对照限定事务 owner 合并、四份转发退出和要求校验；原语句求值、正常查询／更新／提交及后置观察顺序保持。所有 warning 仅传操作标识、已归一化要求和异常类型；未执行状态更新、锁、数据库、业务函数或 Python 测试。

调用者／解析增量完整对照处理器工作树快照与暂存候选，只允许要求验证、通知日志和两个解析异常类型。记录要求校验位于字段修改之前，两条实际通知调用来自该已校验路径；其他处理器草稿不纳入提交。未运行处理器、解析函数、pipeline、SQL 或 Python 测试。
