# Agent Note: 运行设置保留完整数值与隐私开关

Status: implemented

## Problem

观测设置的两个摘要长度，以及运行设置的缓存时长、缓存字节和流式脱敏缓冲字符，使用 parseInt 读取原生 number 输入。合法的 1e3 被写成 1，1.5 又被截成 1，用户输入的预算值在到达既有整数 API 校验前发生改变。

这些区域同时持有隐私开关、显式 false、零预算和条件展示选项。修复数值读取不应顺便把关闭日志变成清空其选项，也不应通过默认值覆盖零值、空脱敏占位符或普通用户导航的现有归一化规则。

## Decision

五个处理函数直接使用 Number 加原有空串零默认。其余字段、min/max、显示默认的空值合并、更新回调键、部分 patch、条件展示与布局保持。小数继续出现在 patch 中，交给原后端整数 DTO 和父保存失败路径处理，不在前端悄悄截断。

三个组件继续使用受控 props；没有本地异步工作，不增加请求 owner、共享 Context、数字表单管理器或回调身份规则。父页面继续持有默认／当前／编辑配置合并、PUT、刷新与失败提示，失败时保留编辑值。原文记录、工具结果摘要和工作流执行路径开关仍各自独立。

导航 owner 经完整复核后保留原文。九个模块与后端允许集合一致，现有 helper 按产品顺序去重和裁剪；开关只改变所选模块，其他选择保留。后端 before-validator 接受的 null 原始列表仍按现有空集合规则处理，不新增前后端归一化入口。

## Alternatives considered

- 保留 parseInt 改动最少，但它把合法指数值当成字符串前缀，并且掩盖有小数的整数配置，无法保留用户的实际输入。
- Number 后再加 Math.trunc 能维持旧整数输出，却继续隐藏本应由既有 API 判断的输入错误，因此不截断。
- valueAsNumber 能读取完整数值，但空输入产生 NaN，需要另建空值规则；Number 加已有字符串零默认即可保留当前空／零协议。
- 抽出通用数字控件可以减少五处短表达式，但会扩大到相邻设置和默认处理；本批只修正原处理函数。

## Consequences

合法指数值能够到达正确的配置字段，零值和隐私开关保持可见。无效整数的小数输入会走原保存失败路径，用户需要修正输入；这比保存一个未经用户选择的截断值更明确。导航和所有视觉结构保留，不增加 API、配置或共享组件迁移。

心跳零值在实际消费者中也保留禁用语义。前端提示 0 禁用，ChatConfig、PUT 与运行配置解析都保留 0；settings GET 直接返回已有的 float 字段，chat_stream_orchestrator 仅保留原有非负下限，不再用 or 10.0 覆盖零。下游 chat_stream_langchain 在 heartbeat_sec <= 0 时直接等待 queue.get，已有关闭心跳的等待策略不变。默认 10 秒仍由配置模型拥有，不在消费点重复推断。

真实 React DOM、Input、SettingsSwitch 和三个 owner 的 37 个场景在修改前产生 10 个指数／小数回归失败和 27 个通过的行为控制。控制覆盖五处空／零、九个导航模块及产品顺序、null 导航输入、隐私开关、条件隐藏后设置保留、空脱敏占位符和心跳零／小数载荷。happy-dom 的指数 badInput 不作为浏览器结论，测试核对 valueAsNumber 与实际 patch；后端拒绝小数只由实际 schema 和未改父保存源码支持，没有运行后端。
