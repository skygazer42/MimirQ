# Agent Note: SAML 原始错误码只读取自有消息键

Status: implemented

## Problem

回调 URL 的 `error` 是原始字符串。普通对象按该字符串索引时，`toString`、`constructor` 和 `__proto__` 会命中继承属性，绕过未知错误的通用文案。真实回调页把结果传给 React setState，前者显示 `[object Undefined]`，后两者产生无效 React child。原页面测试完整模拟消息解析器，不能观察这个边界。

## Decision

消息解析器先检查消息表的自有键，只有实际列出的错误码能返回对应文案，其余继续使用原通用错误。消息表、返回类型、桥接请求和页面逻辑保持原接口。页面测试只模拟桥接请求，实际调用消息解析器，使 URL 到 React 呈现的契约可以被验证。

## Alternatives considered

在页面额外检查返回值类型能防止 React 抛错，但其他解析器调用方仍会收到错误值，因此修复实际原始字符串边界。将消息表换成 Map 也能排除继承键，却改变现有导出的表结构；自有键检查足以保留公共资源与调用方式。

## Consequences

已知错误继续显示原文案，未知错误继续被归一为通用文案，不回显 URL 或后端细节。自有键分支是唯一新增边界检查，由三个真实 URL 的 React DOM 失败复现支持。

原实现的三个页面回归失败，原有成功登录、已知错误与普通未知错误三个对照通过。修复后页面和库测试、真实聊天流组合回归共 14 项通过。检索活跃笔记没有同主题所有者或待处理提案，本记录独立保留本次错误表与页面测试的决定。
