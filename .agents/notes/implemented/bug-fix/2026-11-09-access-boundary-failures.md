# Agent Note: 访问校验保留真实空值并显式处理失败

Status: implemented

## Problem

共享工作树把 TenantMember.role 的读取直接改成 role.lower()，但真实 String 列没有非空约束，旧权限逻辑允许缺失角色进入既有拒绝分支。空角色因此从 403 变成 AttributeError。文档所有者的读取与修复还退出了原有空白修剪，历史空白所有者不能再按原规则比较或修复。

旧预览图片的归属扫描把任意数据库异常转换为 None，随后变成图片 404。可写数据集和旧预览的候选筛选还把所有 HTTPException 都视为无权限／不存在，无法区分已约定的候选拒绝与其他错误。

## Decision

数据集、RBAC 和未分配文档的四个编辑角色入口直接读取实际 role，仅在有值时转小写；空值继续进入原有权限拒绝，不填入 owner、viewer 或空字符串。公开 role_allows 保留原 strip／lower 规则，真实缺失值直接参与原有拒绝判断；ORM 编辑检查继续只 lower，不扩大历史空白角色的权限。

两个文档所有者读取点保留有值时的 strip，ACL 修复仍对缺失、空串和纯空白所有者写入当前已授权账户。用户标识、角色集合、错误状态／文案、查询、事务和原调用顺序保持，没有增加规范化包装或权限管理类。

已有草稿按完整文件快照核对，只将本批完成的 hunk 暂存；其他所有者字段探测或比较改动保持其归属。

旧预览的主归属查询失败直接传播，只有真实没有引用／绑定或无可读候选时才保持原 404。数据集选择和旧预览的三处 HTTPException 筛选仅跳过原有 403／404，其余状态直接抛出，不继续选择其他候选或创建默认数据集。此规则与同模块图像证据过滤的既有策略一致。

原 SQL 租户条件、精确图片引用验证、扫描上限、候选排序、文档／数据集 ACL、侧车写入条件和响应文案保持。API 仍通过既有资源绑定入口调用；流式检索在图像授权前将图像候选初始化为空，并在 finally 释放 Session，错误路径没有使用未过滤图像。

## Alternatives considered

- 无条件 lower 写法短，但无法接受数据库实际允许的 NULL，会改变原有拒绝响应。
- 恢复 or 空字符串可避免异常，却继续把缺失字段改成另一个值；保留原值即可完成已有权限集合判断。
- 在会员查询中统一拒绝无角色账户可集中校验，但会影响原本不依赖编辑角色的读取权限，因此只调整原有角色检查位置。
- 归属查询失败一律返回 404 可以继续隐藏资源细节，但也会把数据库故障报告成资源不存在；既有全局错误入口已经使用通用错误消息，查询故障直接传播即可保持失败可见。

## Consequences

缺失角色继续拒绝编辑，已有大小写和空白规则不变。文档原始 owner 字段不被全局重写；只在既有 ACL 修复操作中沿用原赋值条件。每处真实可空读取保留一次存在性判断，不能按类型注解或 None 数量直接删除。

后端归属查询或其他候选错误会使本次请求失败，调用者不再把它当作图片缺失或触发另一项写入。真实无权限／不存在仍按原响应隐藏资源细节。局部重复 warning 退出，失败日志由既有错误入口负责；不新增重试、缓存、兼容存储或权限默认值。

核对真实模型、角色常量、调用者和当前／已提交版本；完整模块 AST 分别限制本批工作树修正与候选暂存 hunk，其他共享草稿逐节点保持。限定 Ruff／格式、Python 3.11 AST／源码编译和 Note 门禁提供静态证据。按用户要求未新增、修改或运行 Python 测试，未执行权限请求、数据库查询／写入、Session 或业务函数，静态结果不代表真实授权回归。

资源错误增量核对真实 legacy SQL owner、API 资源绑定、图像证据过滤、流式检索的初始化／finally 与全局异常入口。完整模块对照只允许主查询捕获退出、三处状态分类和无用日志绑定退出；全部查询、授权调用、缓存写入和正常返回保持，未执行图片读取、检索、SQL 或失败路径运行时。
