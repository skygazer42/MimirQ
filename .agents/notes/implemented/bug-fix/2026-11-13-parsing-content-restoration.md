# Agent Note: 解析正文读取与任务状态分开

Status: implemented

## Problem

解析恢复的两个入口用空字符串判断是否加载，把用户清空的正文换回原文，还会 trim Markdown 缩进。缓存读取和远端请求失败被吞为 miss/空结果，一些异步库更新没有等待完成，删除或切换文件后还可能发布旧恢复结果。

知识库 parsed-content 的 available 只表示持久化正文或文本源文件可读；正在处理的新任务仍可能有旧正文。把它当作任务完成会提前停轮询；失败后没有正文又可能永远显示正在解析。打开原文件还会进入本地“上次解析中断”分支，使远端任务失去更新链。旧正文优先显示时，错误和重试入口曾被隐藏。

## Decision

特性内的 parsing-library-content 合并两条实际重复的读取流程，分别返回任务 status/error 与可选 content。正在处理的知识库任务读取已有 Document 接口的权威状态，完成后读取正文；失败保留已保存内容并结束轮询。available 与截断字段只判断正文能否完整消费。缓存读取失败交给实际结果区反馈，不静默改读服务器并覆盖本地编辑。

真实空正文和空白直接保留；只在字段没有提供时按既有旧数据合同推导原文/正文。纯恢复总是返回具体对象，调用方消费验证响应的必需字符串。元数据候选在其未知输入边界过滤真正空白，合法 0 和省略时长各自保留。截断结果不写成完整正文。

源文件恢复等待现有 Store 更新，按实际集合引用、挂载和选择检查旧结果，不增加全局版本管理器。知识库仍使用库作为状态/正文所有者，队列、当前文件、目录和计数消费同一投影，真实 File 保留。Query 沿用身份、取消和 refetch；携带客户端起始引用时关闭结构共享，避免 SDK 复用不同快照的引用。两个结果区消费同一错误/重试节点。

本地解析的真实空结果可编辑和保存，保存使用服务器确认的正文/原文。知识库在解析工作台保持后端只读合同；重新解析调用知识库接口，后端确认后才进入 parsing，保留旧正文。当前会话移交不增加持久化承诺。

## Alternatives considered

- 保持两套读取，改动看似更少，但它们已经对同一正文使用不同的空值、失败和元数据策略；只共享实际相同的读取业务，不建立通用请求管理器。
- 用 available 或正文非空代表完成，能少请求状态，但服务端明确允许返回旧正文或文本源文件，已经复现提前完成和永不结束两种错误。因此任务状态与正文分别消费。
- 把知识库任务状态再写回每份队列副本，可以少改视图，但目录和当前项会继续有可独立修改的同义状态；保留唯一库事实并统一投影。
- 将所有库更新强制持久化，可以统一 Promise 失败，但当前会话恢复和移交有已定义的内存工作方式，继续沿用既有 Store 合同。

## Consequences

真实空值不丢失，失败可见并可重试，任务完成/失败后目录与当前面板一致。代价是正在处理的知识库任务需要查询权威文档状态；读取失败停止自动轮询，由用户可见重试恢复。IndexedDB 与服务器不组成跨系统事务，也不声明当前会话更新等于持久保存。

修改前纯函数 4 项和 Hook 9 项回归失败；当前 60 项定向、完整 verify 的 196 文件/1,434 项及静态/类型/API 检查通过。三个 Edge 流程实际覆盖空正文、编辑/清空/保存、刷新读回、知识库只读、原文件读取失败和键盘重试、任务失败保留旧正文。截图已查看，HTTP 为 fixture，页面和浏览器缓存真实。没有启动后端、模型、数据库或重复生产构建。

五份短文件全文核验，其他消费文件保持局部审查；固定来源、写法/命名与验证记录在 .frontend-structure/20261112-full-frontend-guidelines/parsing-content/。整个前端目标继续有效。

队列删除、上传确认、解析目录归属及共享确认等待由[确认结果所有权](2026-11-13-confirmation-mutation-results.md)进一步核验，本篇正文读取与权威任务状态的决定保持。
