# Agent Note: 浏览器 Store 只恢复数据字段

Status: implemented

## Problem

文档查看器把浏览器数据断言为状态后整体合并，缓存字段可以覆盖真实方法，错误布局也会让打开文档失败。解析库只在 migrate 中恢复结构，但当前 Zustand 对相同版本直接调用 merge；当前版本的无效字段因此绕过校验。文件条目还仅检查对象后断言为 ParsedFileData，缺失 filename 的对象会让治理列表报错。

JSON 语法或 Storage 读取失败发生在 merge 前。SDK 的失败回调不提供恢复后的 state，原反馈因此消失；同步初次构造还可能覆盖已设置的失败状态。页面挂载的目录选择和在途列表/正文回填随后仍可改写坏缓存或有效内存文件。仅在适配器写入时抛错又晚于 Zustand 的内存变更，删除和等待中的正文更新会先改数据再报告失败。

## Decision

两个 Store 在实际 merge 入口选取数据字段，保留当前实例的方法；文档视图继续核对身份范围。解析库的当前版本与旧数组格式共用同一恢复实现。文件、解析元素和治理评审按实际模型核对，沿用无效条目过滤政策；合法 null、省略、0、false 和空字符串按对应字段合同保留。

元素校验的纯模块位置及两条 metadata 恢复入口的一致性见[解析元素与时长恢复合同](2026-11-13-parsing-metadata-contract.md)；本篇文件恢复和错误前置条件继续适用。

调用方提供的文件 ID、时间和数组直接使用，不再转字符串或补当前时间。恢复的文件夹必须有实际时间字符串，活动目录必须存在于已恢复集合，否则使用既有根目录。当前时间只用于真实创建新记录。

文档选择在入口规范化一次，当前选择与历史恢复目标同时更新；重新打开消费已恢复的数据。预览锚点的实际接收类型为 unknown，由已有字段校验构造结果。缓存重试和内存模式延续已有合同；正文未完成写入的接管和取消由[局部缓存写入记录](2026-11-12-browser-cache-partial-writes.md)持有。

文件夹移动只操作明确请求的目标。目标不存在、自身、后代或祖先链已循环时返回 false，不再改为移动到根目录；合法目标或根目录仍可移动。

PersistStorage.getItem 返回原生 Promise，让恢复结果在 Store 构造后发布；这没有改变 localStorage 本身的同步 IO。恢复错误保留原值和当前文件，并由两个工作台提供明确反馈和重试。没有快照时保留当前内存，显式快照仍经过字段恢复；旧版本成功恢复后清掉旧错误并允许迁移写回。当前容器/集合验证、单层编码及不可读重试保护由[本地文档保存确认](2026-11-13-browser-document-save.md)明确，本篇不再把错误结构作为正常空库。

恢复反馈及失败期间的目录浏览只更新内存视图，真实索引变更在副作用之前检查读取错误；等待正文写入后再次检查再提交内存。适配器保留落盘边界检查。解析列表和正文的提交 effect 按当前恢复状态检查，异步拒绝在后台边界报告。失败保存保留草稿，不清除修改标记或显示成功。缓存不可用的既有内存模式继续保留。

恢复成功后的正常目录删除与在途变更归属由[文档库按来源和读取起点同步](2026-11-13-document-library-reconciliation.md)处理；本篇的恢复失败前置条件继续适用，不把同步修正外推为内存模式显式保存已验证。

## Alternatives considered

- 只把 Root 状态改为 Partial 断言可以减少类型错误，但运行时仍会接收方法覆盖与错误字段，因此不作为恢复校验。
- 只在迁移时恢复可以保留旧实现，却不处理同版本读取；实际 SDK 的合并入口必须消费已知数据字段。
- 为每个页面复制判断能阻止部分报错，但不能让共享状态形成稳定合同；校验集中在存储恢复，正常写入继续使用已有类型。
- 对没有快照的恢复一律返回空状态，代码短，但会清空合法的内存文件；认证切换已经先清空旧范围，保留 current 不会带回旧身份数据。
- 在适配器里统一跳过错误后的写入，能保住原字符串，但真实保存仍会被当成成功；只在适配器抛错又晚于内存变更，因此检查位于真实 action 及异步提交点之前。

## Consequences

十项原恢复失败、坏好文件混合、伪造时间及无效移动目标均有修改前失败记录。字段恢复切片的六文件 84 项验证及 Edge 关闭/恢复流程保留原范围。读取失败切片新增的五文件 84 项回归通过，完整前端 verify 的 1,346 项用例通过；Edge 从坏索引初次载入、跨两个工作台反馈、恢复重试，再完成编辑保存和刷新读回。HTTP 与会话为隔离 fixture。

独立复核发现的文件项断言、挂载覆写、在途回填和变更先于拒绝问题均已修正，并有实际修改前失败记录。代价是恢复反馈与数据变更必须分别处理；读取失败的写入前置条件也必须在 await 后重新检查。源码合同、范围、逐声明命名与命令结果在 .frontend-structure/20261112-full-frontend-guidelines/shared-stores/ 和 storage-read/，不作为其余工作台全文合格结论。

活跃笔记检索命中的文档 Hook/Mutation 笔记持有服务端操作归属，管线偏好笔记持有另一组 Context 初始化，均不承担本次 Store 恢复决定。本记录不替代这些原有政策。
