# Agent Note: 向量路由错误不能成为空检索成功

Status: implemented

## Problem

未知 VECTOR_BACKEND 返回占位 store，检索空数组、删除不执行，调用方无法区分无命中和后端未实现。区域后端 JSON 损坏或不是对象时，又静默选用主后端，可能访问与配置意图不同的存储。

## Decision

factory 对未知有效后端名抛出 ValueError，退出只有空成功和不操作行为的 StubVectorStore。已支持的 Milvus、memory、Qdrant、pgvector 路由、FAISS／Chroma 的退出错误、缓存身份、模型指纹、排序、预算和删除规则保持。后两者仍是已存在的进程内开发 scaffold，本决定不把它们宣称成远程数据库客户端。

VECTOR_REGION_BACKENDS 按 Settings 已声明的字符串读取，再在这一配置边界解析 JSON。空字符串与空 entry 沿用既有语义；损坏 JSON、非对象或非字符串 backend 值明确失败。JSON 对象 key 自身就是字符串，不重复探测；没有生产写入方的 Mapping／任意对象兼容分支退出。区域名归一化和覆盖优先级保持，未出现区域 override 时仍按已选主后端工作。

只有配置确实参与区域选择时才解析，不为未使用的输入增加全局预检。缓存中的必需配置值直接按声明的字符串读取，保留原哈希输入、fallback 规则和锁；不新增备用后端、模型客户端或迁移行为。

## Alternatives considered

继续返回占位 store 可以让原型界面保持成功响应，但会隐去错误配置和未执行的删除。解析失败后加 warning 继续主后端能减少中断，却仍会路由到错误目标；错误应由调用入口处理。

把所有后端合为内存实现能减少类和文件，但会改变既有 provider 身份、ID、元数据与并发行为，也违背保留其他已选后端的约定。当前只退出虚假的未知后端成功，不扩展或退休有效选项。

## Consequences

使用坏区域映射或未知后端会失败，运维需要修复实际配置；正常无数据仍可空返回。基线与新实现的有限假依赖探针核对支持路由、缓存、作用域与排序，同时证明坏配置不会继续选主存储。

完整应用冷导入和 OpenAPI 只证明声明及组装，没有执行真实索引、检索、Embedding、数据库或 SDK。开发 scaffold 与生产持久存储的差异仍存在，不能从本次重构推导数据持久性或迁移已验证。
