# Agent Note: 本地文档保存确认与正文加载

Status: implemented

## Problem

治理页面先直接写正文，再调用 Store 再次写同一正文；索引存储不可用时，后一步会只改内存却继续显示保存成功或导航。刷新后的空占位草稿还被当作正文，批量切块跳过缓存读取，把已有正文和原文清空。

恢复器将错误根/集合结构补成空库。SDK JSON 包装器又把缺失 state 等错误容器看作无快照；更隐蔽的是已知坏索引在无存储重试后会清除 loadError，能力恢复后仅浏览目录便覆盖原始坏值。正文后台写入和两类缓存清理则交给静默 detachPromise，失败没有明确归属。

## Decision

Store 是治理显式保存的唯一写入所有者。updateParsedFile 的具名 requirePersistence 选项只在需要确认浏览器写入的入口启用：先检查已有读取错误与存储能力，等待正文写入，返回后再次检查能力、范围、取消和目标存在，再确认索引写入。失败直接交给现有保存反馈，草稿不清除、不显示成功、不导航。日常工作副本与当前会话的“继续治理”保留已有内存合同，不因为它们经过同一更新方法就增加持久化承诺。

治理工作状态明确记录 contentLoaded。元数据中的空串不是可保存正文；成功缓存/API 读取和真实预览上传才确认加载，包括合法空文本。批量目标无已知正文时直接读取其保存内容，不要求逐份打开；真实清空不回退到旧正文。正文缓存读取失败显示已有重试，不伪装 miss 并覆盖为远端正文；本地文件没有猜测远端身份。知识库 available:false 不是空文档，必需字符串按真实响应合同消费。

PersistStorage 直接解析一次并核对 state/可选版本，写入编码一次，格式保持。真正没有键仍支持内存模式；错误容器、错误集合与真实空数组分开。旧数组、files-only、无版本格式保留原接受范围，坏条目过滤政策保持。无法读取的重试保留已有失败，只有有效实际读取才能解除保护；恢复反馈与失败后的浏览不写回原索引。

在途任务继续按范围/身份管理和继承已接受补丁。无依据的三次即时重试退出；可选后台缓存失败告警，清理尝试正文/源文件两个缓存并记录失败。身份恢复由 SDK 与实际 generation 管理，异常有边界；没有为此新增类、全局管理器、影子数据源或依赖。文件/目录回调按实体命名，真实共享审核数组直接派生类型。

## Related decisions

本篇接管[局部缓存写入](2026-11-12-browser-cache-partial-writes.md)的三次重试和治理父页面预写正文策略，保留其同事务局部合并、清空、接管、取消及身份隔离决定。[Store 恢复](2026-11-12-browser-store-restoration.md)的错误保护继续适用，容器/集合、编码和不可读重试由本篇明确。[治理父工作流](2026-11-05-governance-parent-workflow.md)的重置、上传取消、原文配对和工具偏好继续成立，保存所有权及加载标记由本篇接管。[元素与时长](2026-11-13-parsing-metadata-contract.md)的独立纯函数与字段合同继续适用。

活跃笔记检索的命中均为部分重叠，按上述范围互链；没有同一问题的待落地提案需要拒绝或归档。其他业务工作台与其余恢复/请求消费代码不因这篇记录计为全文通过。

## Alternatives considered

- 保持正文双写并在页面探测存储，改动看似少。但实际失败归属、缓存完成和索引写入仍分开，探测成功也不代表写入完成，因此由真实 Store 方法确认所需步骤。
- 全部更新都强制落盘，可统一失败合同。但已验证的会话移交和临时工作副本有实际内存可用需求，因此只在明确保存入口要求持久化，不改变其他入口的承诺。
- 用正文是否为空或草稿是否存在判断加载，能省一个字段。但真实清空、尚未加载和缓存读取失败会混在一起，已经产生实际清空，因此保留一项真实加载事实，退出空文本启发式回填。
- 继续使用无校验的 JSON 包装可以直接消费 SDK，但合法 JSON 的错误容器会被视为缺失，错误集合会变空库。直接实现公开 PersistStorage 对象协议，在所有者验证必要结构，不建立另一套序列化框架。
- 保留三次即时重试可能偶然越过短暂问题，但它不区分拒绝、权限或容量错误，没有当前可恢复分类依据；显式保存由用户可见重试完成，可选缓存失败告警并保留工作副本。

## Consequences

显式成功只在正文和索引均获确认后出现；失败可重试，未加载占位不再清空正文，真实空编辑仍保存。持久化结构不变，坏结构保留原值而不自动抹成空库。代价是治理读取缓存失败需要明确恢复，不能静默展示可能较旧的远端正文；两个浏览器存储的写入不是跨存储事务，正文已写而索引失败仍按失败报告，不宣称整体成功。

修改前已有 2 项真实页面保存误报、5 项确认/取消、3 项正文加载、2 项后台失败、4 项集合结构、5 项容器结构和 1 项不可读重试回归失败记录；测试环境最初定位/spy 问题另保留日志，不算产品缺陷。当前 102 项定向回归与完整 verify 的 195 文件/1,407 项用例、静态/类型/API 检查通过。

真实 Edge 完成三类存储故障、草稿保留、键盘重试、刷新正文和原文，以及加载中批量提交后读取实际 IndexedDB 确认正文未清空。五项通过与最终批量项通过分别保留日志；两个加载区域的定位修正不改变产品行为。截图已查看，HTTP 为 fixture，浏览器存储与 UI 为实际实现。没有启动后端、数据库、模型或执行生产构建，不宣称真实服务验收。

Store 与浏览器测试完成全文核验，治理组件及其他消费 Hook 保持局部审查。逐声明、固定来源、代码快照和结果在 .frontend-structure/20261112-full-frontend-guidelines/durable-save/；全量前端目标继续有效。
