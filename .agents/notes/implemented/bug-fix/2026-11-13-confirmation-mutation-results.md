# Agent Note: 确认结果与队列变更的所有权

Status: implemented

## Problem

解析删除先清本地对象再等服务器，失败后原条目与缓存已消失。共享确认的 Action 默认立即关闭，detachPromise 又隐藏真正结束与失败；生产回调里还有返回 void 的异步包装和吞错误的操作函数。

批量测试用例任一删除失败就停止后续处理，成功项仍在缓存和选择里。重试再次提交它们，而服务端对已经删除的项返回 404。创建中的解析重试也可能在用户删除后回填新库条目；解析完成及上传批次最终发布还会用旧目录撤回用户移动。

## Decision

ConfirmDialog 使用原有 primitives 和按钮，阻止 Action 的默认提前关闭，等待实际同步/异步结果。失败保留对象和重试，处理中阻止重复、取消及 Escape；组件结束后不再调用旧父级或回写自己。内部说明保留真正缺失与合法 React 内容的区别。错误文字约束在实际 grid 项内，组件拥有视口高度与滚动边界，保留标签占位让按钮等待时不跳宽。

实际确认调用方直接返回操作 Promise，失败继续传播；透明 detach 包装与确认路径重复失败提示退出。读取类动作仍在其已有反馈边界消费错误，不新建统一请求/事务管理器。三个 ops 确认在服务真正完成后发布各自结果。

队列远端删除确认后才调用 Store 移除记录，Store 是两份缓存清理的唯一所有者；纯本地预览不猜测远端身份。现有读取错误在请求发出前拒绝；挂载、身份范围和会话决定结果归属。成功只清目标选择，不清用户后来选择的对象。目录清理把真实移除文件 IDs 传到队列并取消对应任务。

无服务器 ID 的上传阶段不提供永久删除，动作入口也明确拒绝。取得 ID 后恢复正常删除。目录操作本来只清本地组织与记录，说明明确服务器文档保留；取消本地任务后的创建响应不再回填旧条目。上传和 metadata 写入分开承认，后者失败仍保存已确认 ID/source。服务器名称、时间、0 字节直接消费，不补造数据。

上传批次最终发布按当前库确认存在与目录，不重新发布用户已删对象；解析结果不再持有目录字段。运行使用既有唯一身份生成器，时间只作真实观察和耗时。自动入口和失败回填有明确报告边界。

测试用例删除等待 allSettled，按输入顺序对应 IDs；先将确认成功项从当前缓存/统计/选择移除，再刷新，失败项继续在原确认中重试。父级选择读取当前引用，失效组件/身份不发旧通知。没有把 404 当作成功，也不增加即时重试。

## Alternatives considered

- 乐观移除再回滚可以更快隐藏条目，但失败期间的新编辑、选择和缓存写入需要另一套恢复约束；直接等待服务器可以保留原对象与完整上下文。
- 只给删除函数加 await，看似局部，但弹窗和 void 包装仍会丢失结果，因此沿实际全部确认链迁移。
- 批量继续 Promise.all 接口最短，但它不能表示独立部分成功；逐项确认后只重试失败项，不创建并发池或批处理框架。
- 未拿到服务器身份就先取消并移除，界面结束最快，但不能撤销服务器创建，后续目录会出现刚被“永久删除”的项。因此只在这个真实阶段暂不可删除，不一律禁止解析中的删除。
- 同时保存另一份队列目录可以少查 Store，但实际复现库与队列互相覆盖；最终投影只读取当前所有者。

## Consequences

失败不丢对象和缓存，部分成功可正确继续，处理中与本次结果有明确归属。取得上传身份前必须等待，错误保持在确认里而不会自动消失；长文本在窄窗口也保留可读内容与操作。浏览器存储和远端服务不是跨系统事务，现有日常内存工作合同没有被改成全面持久化承诺。

删除两份无生产引用的旧解析侧栏/移动队列和其源码字串测试，共 606 行，实际页面沿用当前 Shell；文档图按实际 imports 更新。规则、逐声明、固定原文和日志在 .frontend-structure/20261112-full-frontend-guidelines/queue-confirmation/。五份短文件全文，其余大文件按范围核验，整个前端目标仍未完成。

核心 79 项回归及完整 verify 的 197 文件/1,456 项通过，真实 Edge 1280×720、390×844 两条流程完成失败保持、禁用提前退出、键盘重试、原生缓存删除与刷新。截图已查看；HTTP 为 fixture，没有启动后端、数据库或模型，也没有生产构建、提交或部署。中间 fixture/动画测量失败与真实长文本溢出分别保留日志。
