# Agent Note: 跟进检索的查询和诊断遵守同一个词数上限

Status: implemented

## Problem

证据缺口已经提供 max_terms 个候选词时，文档候选循环仍追加一个词后才检查上限。查询因此包含三个扩展词，诊断 selected_terms 却只报告前两个，实际查询和预算说明不一致。

## Decision

缺口候选前缀已经占满词数预算时，直接返回该前缀。唯一公开构造入口已经保证正的上限，并将缺口候选限制在该上限内。未占满时仍按原分数、顺序和去重规则补充文档词。

## Alternatives considered

只截断诊断可保持旧查询，却继续让真正发出的查询超预算。拼好查询后再截断字符串无法按词数保证一致，也可能切坏一个候选词，因此在选择扩展词的责任边界结束处理。

## Consequences

满预算缺口不再多发一个扩展词，查询与 selected_terms 一致。零预算、无文档、文档预算、查询字符数、原因码和排序语义保持，不增加模型调用、重试或备用查询策略。

原源码的满预算反例单独保留，修后只做有限的选源观察，覆盖满额、未满、无缺口和原关闭路径。没有执行实际检索、模型、数据库或应用测试；词数修复不代表其他检索预算都经过重新验收。
