# Agent Note: 检索缓存身份计算失败直接传播

Status: implemented

## Problem

LangGraph 的检索缓存 key 回调在嵌入空间计算失败时写入空字符串，策略 JSON 序列化失败时改用 `str(policy)`。这把无法确定配置身份的请求转成一个可缓存 key；不同失败可能落到同一身份，对象文本也不是原有的规范化 JSON 表示。

## Decision

`_retrieve_cache_key` 直接计算嵌入空间标识并序列化已归一化的意图策略。失败交给 LangGraph 的原 key 回调错误路径，不生成空空间或另一种策略编码来读写缓存。正常配置的 JSON、hash 算法、字段及顺序保持，真实未提供策略时仍沿用原空策略标识。

key 回调仅在图缓存已启用时参与该缓存策略。嵌入工具仍在原阶段延迟导入；不增加模型请求、依赖初始化时点、重试、第二缓存或配置开关。此决定只限定缓存身份失败处理，不把它当成整个 key 字段覆盖或跨服务缓存一致性的证明。

## Alternatives considered

- 失败后使用空字符串和对象文本能继续查询，但 key 不再代表实际配置，可能复用另一请求的缓存结果。
- 随机生成 key 可以避免碰撞，却让缓存身份失去确定性并隐藏配置错误；本 callback 没有既定的禁用单次缓存返回值，不能以新编码伪造成功。

## Consequences

缓存身份无法确定时请求失败，需要修复配置或序列化输入；不再把身份计算错误表示成合法缓存 key。缓存关闭时继续使用既有非缓存流程，正常 key 不变，本次没有统一扩大或缩小租户／文档范围。

验证核对实际 Settings 声明、嵌入 hash owner、策略 normalizer 和安装版本 LangGraph 的 key 回调调用点。完整模块 AST 对照仅允许两处异常包装及重复空初始化退出；Ruff check/format、Python 3.11 AST／编译和 Note 门禁通过。按用户要求未新增或运行 Python 测试，未执行缓存、模型、数据库、LangGraph 请求或业务正则。
