# Agent Note: 解析失败恢复与目录索引提交边界

Status: implemented

## Problem

解析异常的诊断直接断言类型，非法数组/摘录会让错误页面崩溃。目录行内重试传库 ID，解析入口却只找队列 ID。原文件读取异常与 miss 混在页面局部状态中。坏目录图可能含循环、重复身份和缺父。

Zustand persist 先改内存再写索引，拒写留下已改变的目录/文档。非 parsed 正文更新还会提前取消旧 owner 并启动替换缓存写。正文长度也无法区分真实双空串与索引占位，会误读旧缓存。

## Decision

诊断在接收处按实际后端结构验证，类型从同一 schema 推导。非法补充诊断不进入页面，主失败、已有正文和重试保留；零、false 和空摘录按真实合同显示。

原文件可用性、错误与重试由现有按库 ID 的 Query 持有，删除同义 PageState。库 ID 重试先选择并恢复目标，再通过既有队列解析；本地缺源只提供实际关联。自动恢复归库动作，从读取开始复用已有每文档 controller，后来的人工关联使旧任务失效。

`contentLoaded:true` 表示会话已经获得正文，可以是双空串。预览、解析、内容读取和正文更新负责产生；索引不保存，恢复索引清除。真正需要的缓存读取失败仍然可见；已确认的可选内存模式保留，显式保存仍等待持久化。

Store 统一负责索引拒写回滚。目录图验证身份、父级和无循环后恢复；失败保留原始 JSON 和当前对象。删除缓存、取消旧正文及替换立即写 owner 等副作用跟随已接受的对应索引提交。目录输入边界提示实际异常并保留名称/目标；失败不关闭移动弹窗。创建与切换是两笔既有提交；创建完成后关闭其入口，切换失败明确说明已创建。

## Alternatives considered

- 渲染时逐处判数组改动少，但异常有多个消费者；接收处验证并派生类型可以避免维护不同合同。
- 自动挂载前只检查是否已入队更短，但覆盖不了新关联仍等待缓存写入；复用已有文档拥有者才能表达真实先后。
- 按正文长度判断无需新字段，但无法区分合法双空串与索引占位；只保留一个明确会话事实并禁止落盘。
- 索引失败只回滚 files 更短，但目录、位置及已取消正文仍变化；恢复整个先前 Store，并在提交后执行对应副作用。

## Consequences

错误页面保留主失败、已有正文并可重试；新关联不被旧恢复覆盖，空正文不被旧缓存替换。坏图原文可以修复后重读；拒写保留对象、位置和旧正文。代价是实际外部结构与提交需要相应校验/错误边界，加载事实需在真实 producer 维护；没有备用权威存储或默认成功。

验证见 `.frontend-structure/20261112-full-frontend-guidelines/parsing-failures/`。HTTP fixtures 与真实前端缓存只证明本批前端流程，不代表解析服务或全部前端已验收。
