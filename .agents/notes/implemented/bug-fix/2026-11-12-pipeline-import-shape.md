# Agent Note: 管线导入错误不能替换成默认偏好

Status: implemented

## Problem

用户导入 null、数组、数字或字符串时，旧 importJson 把它交给偏好规范化函数，得到默认选项后仍返回成功。导入面板于是关闭并清空文本，已有偏好也被替换。包装对象的 options 为 null/数组或 enabled 为字符串时同样没有被拒绝。正常化损坏本地存储的政策被错误地用于用户主动导入。

## Decision

importJson 先解析 JSON，再检查根对象及包装字段，形状错误在修改状态前返回。裸配置对象与 { enabled, options } 两种格式继续支持，实际 options 字段仍由既有规范化函数处理；未增加逐项配置参数的新校验政策。

返回类型使用 ok 字面量区分成功与携带必需错误文本的失败。面板及三个预览消费者直接消费错误，不再为确定存在的错误增加替代消息；侧栏退出未被实际使用的 errorMessage 配置。面板仅在成功后关闭和清空文本，失败保留输入及已保存偏好。

存储恢复继续使用原有默认值政策，与主动导入的失败分支分开。逻辑计算不被宽泛 catch 伪装成用户输入错误；JSON 解析错误仍有明确结果。

## Alternatives considered

- 保留统一的未知值正常化可以接受更多 JSON 值，但会把格式错误误报为导入成功，并覆盖已有偏好。
- 只修改面板可阻止该入口关闭，但三个程序化导入消费者仍会得到错误结果；因此形状检查和结果合同由实际导入动作持有。

## Consequences

修复前新增的七个形状失败用例全部复现错误成功；修复后拒绝这些输入并保留持久化内容。合法裸对象、包装对象及 enabled:false 继续正常导入。挂载真实面板和 Context 的用例验证失败保留弹窗/文本、随后成功更新与持久化，相关四个文件的 38 项测试通过。

Edge 另从治理配置真实入口验证错误文本保留、合法导入和刷新后导出读回。HTTP 与剪贴板写入为隔离替身，持久化和重新加载使用实际浏览器。测试按清洗规则分区识别导出操作，避免与治理预设的同名按钮混淆。

精确检索活跃笔记没有相同导入动作决定；命中的两个后端领域/工具笔记与此无关。本记录与[管线偏好初始化](2026-11-05-pipeline-preference-initialization.md)部分相关，初始化政策保留，本记录单独持有主动导入的错误边界。实际来源、代码范围、命名与验证位于 .frontend-structure/20261112-full-frontend-guidelines/global-components/。
