# Agent Note: 文档库按来源和读取起点同步

Status: implemented

## Problem

治理上传预览和未绑定服务端的解析编辑提交确实生成本地文件，载荷不带 source。解析工作台却用首 200 条远端响应替换共享库，还将当前数据集过滤带进同步。切换工作台或范围后，本地预览、其他数据集和失败来源的文件会从共享库丢失。映射重建记录还会丢弃治理状态，把有效的 0 换成默认值。

治理已有分页也可能把提前空页视为成功结束，随后用不完整集合确认删除。只保留成功来源而不展示另一来源失败，会让用户误认为目录已同步完成。两个工作台都需要保护请求期间确认的新增、编辑和删除，旧读取不能重新恢复用户已删除的记录。

## Decision

共享文档库继续持有本地工作副本。完整远端目录读取不受页面数据集筛选影响，筛选仅计算可见视图。source 缺省表示实际本地文件；parsing_workspace 和 knowledge_base 分别由对应的成功来源确认。两来源独立结算，失败保留当前记录并提供可见重试；两来源都失败不写入空库。

两个实际消费者复用一个分页读取函数和一个纯合并函数。页读取等待当前响应，用已读数量作为下一次 offset，保留服务端 total，并拒绝观测到的总数变化、重复 ID、提前空页和超额。Query 的 signal 通过已有请求选项传入实际 Axios 请求；每次 await 后和聚合结束后检查取消。新查询键区分旧数组和当前带起始引用的结果形状。

读取开始时保存按 ID 索引的 Store 对象引用。提交前从 Store 取最新集合，成功来源只删除起始记录仍未改变的缺席项；远端记录也只有起始与当前引用相同才覆盖。请求期间新增、编辑和删除的条目因此保持。引用只表示当前不可变 Store 合同下的记录版本，实体合并仍按 ID，不新增全局 revision 或第二套状态所有者。

远端映射接收该 ID 的已有记录并保留本地字段。必需文件名、类型、大小和时间直接使用 DTO，不伪造大小或当前时间；只有新摘要初始化空正文。合法时长 0 保留，真实空错误不经字符串兜底。元素校验与时长读取的当前决定由[解析元素与时长恢复合同](2026-11-13-parsing-metadata-contract.md)进一步接管；映射其余兼容策略不因这次同步修复计为全文合格。

## Alternatives considered

- 保留首 200 条或当前筛选响应，能限制读取量并直接填充可见列表。但共享库还供其他工作台和数据集使用，响应缺席不能代表整个库已删除，因此读取完整目录后再过滤视图。
- 一来源失败就拒绝整个合并，失败语义简单。但另一来源和本地文件仍有用，现有业务允许分别可用，所以保留逐来源结算并显式反馈失败，不补造空集合。
- 保留原先首 total 与空页停止方案，可在远端变化时尽快结束。但不完整集合不能有删除权，所以已观察到的异常页使对应来源失败，用户可以重试。
- 两个工作台各自继续合并，能保持本地实现独立。但在途删除与失败删除的规则相同，曾出现一处保护新增而另一处恢复删除的差异，因此只共享这项具体纯规则，不增加通用同步框架。
- 为每条记录新增版本计数，可以表达写入发生。但当前 Store 的实际写入已生成新对象，起始引用足够表达本次读取期间的变更，无需再维护同义版本状态。

## Consequences

本地预览、失败来源和读取期间的新操作保留，超过一页的远端文档能进入共享库；失败和正常空目录有不同界面，弹窗内也能重试。代价是完整目录需要额外分页请求，起始引用按本次读取存活。总数或排序在分页期间变化时，前端只拒绝已观察到的不一致；当前服务端没有事务快照或游标令牌，不能承诺检测所有总数不变的并发修改。

三个实际相关文件共 48 项定向用例通过；完整前端 verify 的 194 文件、1,361 项用例及静态、类型、API 检查通过。Edge 完成真实治理上传预览、保存、解析目录、刷新后的来源失败保留，以及弹窗内重试恢复；HTTP 是受控 fixture，UI 与浏览器存储为真实实现。没有据此声明真实后端联调或所有生产文件达标。

独立复核发现的分页漂移、部分失败无反馈和删除复活均已修正。逐段代码/固定来源证据及逐声明命名记录位于 .frontend-structure/20261112-full-frontend-guidelines/library-sync/；元素与时长的后续证据位于相邻 element-contract/。内存模式保存反馈和其余前端内容继续待审，全量前端规范目标仍在进行。
