# Agent Note: JWT 辅助模块尊重有效期与缓存配置

Status: implemented

## Problem

JWT 签发辅助函数需要区分未指定有效期与显式零；远端密钥缓存需要在刷新失败时检查实际缓存年龄。使用布尔默认会扩大零值配置，使用刷新前的时间则可能在等待后返回超过允许时限的缓存。当前签名密钥若被验证侧裁剪，也会改变参与签名的字节。

## Decision

`jwt_utils.py` 仅在 expires_minutes 为 None 时采用配置默认，其他数值继续遵守既有一分钟下限。`jwt_verify.py` 直接使用 Settings 已验证的 TTL、超时与陈旧窗口；JWKS 与 OIDC 刷新失败后重新读取单调时钟，按当时年龄决定能否沿用缓存。零窗口有效，等于窗口上限的既有比较规则保持。

当前 SECRET_KEY 候选保留签发使用的原始字符串。SECRET_KEY_FALLBACKS 继续采用去空白的逗号分隔配置，不承诺编码首尾含空白的旧密钥；需要这类轮转时应单独设计可无损表达的配置格式，不能悄悄改变现有 CSV 含义。

缓存锁、刷新与取消策略由原辅助模块持有。刷新失败超过时限时继续传播原异常，缓存回退有日志且不延长配置窗口；成功拉取后的原缓存写入时间与 TTL 计算未在本次重设计。

## Alternatives considered

统一裁剪当前与候选密钥可以让文本配置更宽容，但签发已经使用原始字节，裁剪会拒绝本模块签发的有效令牌。自动把零值替换成推荐默认能维持常见配置，却会改变用户显式设置的时限。

继续使用开始刷新的时刻可以少读两次时钟，但不能满足有限陈旧窗口。重写缓存、锁和远端客户端可以一并管理获取预算，却超出此次两个实际时间判断的修正范围。

## Consequences

显式零有效期仍受原一分钟下限约束，不表示立即过期。缓存刷新等待使年龄跨过时限时会失败，而不是接受过旧材料。旧 Python 测试中若固化被默认值覆盖的行为，需要独立维护；本任务不改、不跑这些测试。

合成配置、签名材料与假时钟探针核对有效期、原始密钥、零窗口、窗口内／等于／超限、并发和取消。未请求真实身份提供者或验证部署中的登录链路；辅助函数的离线正确性不等于整套认证服务已完成集成验证。
