# Agent Note: 治理工具的请求归属与原文坐标

Status: implemented

## Problem

治理工作台切换文件时保留当前工具组件。质量检查、清洗、分类和标注的旧请求仍会发布结果；只比较文本也无法区分内容相同的文件，以及离开后再返回的访问。重置或手动修改期间，旧请求还能覆盖新输入，或清除后续请求的忙碌状态。

标注组件在 React 状态 updater 中调用父回调，Strict Mode 重放会重复发布。自动标注使用裁剪首尾空白后的请求文本，手动选区又可能压缩空白，两者的坐标都可能偏离工作台原文。

## Decision

父面板的四个工具调用使用 `key={selectedFileId}`，由 React 显式界定文件访问。切换到相同文本的另一文件，以及 A→B→A，都结束旧组件的寿命。工具各自持有当前请求标记；内容改变、卸载、重置和新的手动编辑使旧标记失效。响应、错误和完成状态只有在标记仍匹配时才能提交。

父回调身份不参与文件重置或请求失效判断。同步引用只更新当前通知回调，因此普通回调重建保留进行中操作和已完成的本地状态；异步完成使用当前回调，也不会因此重复自动质量扫描。无需新增 fileId prop、Context 或控制器。

清洗请求记录发起时的已编辑文本。外部草稿更新会使待处理请求失效；本工具成功发布后，父组件确认该文本不会清除刚生成的预览。分类及标注同样接收父组件的元数据重置。清洗的第二阶段 LLM 调用仅在规则预览仍属于当前操作时启动；当前 LLM 失败仍保留规则结果。

标注提交从当前本地快照计算去重后的数组，再分别更新 React state 和调用父回调。updater 内不执行父组件或通知副作用。同步引用只负责连续事件和异步合并所需的最新快照，外部 annotations 更新仍是同步入口。

自动标注的请求文本与参数保持原样，将 Python 字符索引转换为 DOM 使用的 UTF-16 索引，并计入被裁去的前导空白长度。索引表只遍历到实际候选的最大 end，不为整份长文构建多余映射。手动选区保留精确匹配优先；需要跨空白匹配时转义文本片段并匹配原文，返回原文范围和原文切片。既有首个文本匹配顺序保持，不推断 Markdown 渲染节点与源码之间的新映射。

组件直接从现有 API 与 DTO 所有者导入。API 已归一化的标注数组直接使用；可选清洗统计、可空元数据和原有输入边界仍保留其处理规则。样式、文案、提供方、预算和清洗载荷保持。

提示词选择读取完整的活跃模板集合，保留每页 50 条及原有排序，按第一页 total 与空页结束后续读取。它在现有 prompts 前缀下使用独立 selection key，避免聊天组件的 50 条页面缓存覆盖选择集合。QueryClient 的 signal 阻止工具卸载后继续读取下一页，不声称取消已发出的 HTTP 请求。

## Alternatives considered

- 只比较请求文本，代码更少，也能处理普通文本切换。但相同内容的不同文件和 A→B→A 会被误认为同一操作，因此使用每次操作的独立标记及既有文件回调归属。
- 用按文件 ID 缓存的父回调代替文件身份，可以局部区分实际父面板中的文件，而不改挂载点。但普通回调重建也会取消请求、重置结果，这个隐藏约束过强。文件身份使用 React key；当前回调更新与生命周期分开。
- 只在父面板按文件 ID remount，可以清除局部状态。但它不能代替已发起请求的失效处理，也无法处理同文件内的重置和两阶段清洗。因此 key 负责文件寿命，工具内的请求标记负责当前操作。
- 只依靠 AbortController 可以减少未完成工作。但现有管线 API 方法不接收 signal，扩展传输层超出本次类别；即使支持取消，也仍需拒绝过期响应。这里不声称取消已有 HTTP 请求，只阻止过期发布与后续 LLM 阶段。
- 在函数式 state updater 内发布能方便地拿到最新数组。但 updater 必须可重放；最新快照计算与一次性父回调分开执行，避免 Strict Mode 重复发布。

## Testing

真实 React DOM、QueryClient 和 PipelineOptionsProvider 运行工具；仅网络、翻译、通知及所属范围外的配置面板边界受控。初始 33 个场景中，24 个回归失败、9 个现有成功或失败策略控制通过；补充的父重置 5 场景中，3 个失败、2 个自身发布确认控制通过。坐标补充场景复现 emoji 前缀的索引错误，并检查标点不会被当作正则语法。提示词场景复现第 51 条模板无法选择，并验证选择可传给 LLM 清洗、聊天缓存保持原样以及卸载后停止翻页。挂载测试明确使用文件 key；另 9 个回调重建场景在旧实现失败，覆盖进行中工作、完成状态、最新回调和自动扫描不重复。完整结果随类别报告保存。

活动笔记按四个组件路径、名称及选区函数检索，没有同一所有者的既有决定需要吸收或改写。新增笔记使用现有目录和校验脚本，不增加 CI 或项目配置。

## Consequences

请求继续使用原有 API，可能在后台完成；过期结果不会写回当前工具，也不会启动下一阶段。每个组件需要维护少量请求与同步状态，未来增加输入、手动编辑入口或回调时，需要检查其是否改变操作归属。

这些工具的状态和编辑规则不同，不合成配置驱动框架或共享 Context。DOM 测试验证请求与提交语义；本次不启动浏览器或服务器，不以此声称视觉、布局或浏览器选区的全量验收。
