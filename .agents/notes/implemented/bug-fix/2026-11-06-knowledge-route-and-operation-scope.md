# Agent Note: 入库路由访问与并发动作持有实际范围

Status: implemented

## Problem

Root 对 028dd 的独立 DOM 回放发现两处本批回归。路由 A 已应用、手选 B、经过暂缺目标 C 再显式回 A 时，旧 applied ref 仍记为 A，忽略新访问。隔离队列的全局 actingRef 又会拦截无关文档 B，而实际审核抽屉只把当前文档的动作标为忙，B 按钮仍启用。

补充真实 File／forwardRef／QueryClient 回放证实，DropZone 的组件全局上传引用也吞掉 B 数据集、不同 File 批次或新确认访问的提交；公开 Promise<void> 还会在重复请求的实际上传未完成时提前 resolve。原上传实现允许不同批次，每批 max_concurrent 为四，没有整个组件只允许一批的合同。

## Decision

操作页保留原 applied ref，并另记已观察的 URL 值。每次 URL 值变化即退休上次应用身份，包括当前列表暂缺的合法目标；同一访问的元数据刷新不退休。目标稍后可用时仍应用一次，已应用后不覆盖手选目标。没有新增 Hook 或路由管理器。

隔离动作按真实文档 ID 保存当前请求身份；React 只持有该请求表的只读显示快照。每个 finally 只移除自己的文档与原请求对象。审核抽屉读取 selected.id，调参对话读取 target.id 对应的真实动作；调参忙状态也按目标判断，避免规则管理打开同一文档时出现启用但无反馈的保存按钮。不同文档可以同时操作，同文档同步重复操作仍只提交一次。原逐 await 会话校验、接受写入后的缓存刷新和旧调参访问保护保持。

DropZone 在原组件内记录实际未完成批次与完成 Promise。仅在同确认访问、认证修订、目标、解析器、评估模式以及同序的真实 File 对象全部相同时复用完成；不同 File 对象即使名称、大小和 mtime 相同也各自提交。文件列表仅浅拷贝，File 内容与对象保持；不制造内容指纹，不以元数据充当内容身份。

新数据集访问和新确认草稿清除旧 UI 忙状态；完成仅移除自身批次，并按当前访问的剩余批次判断 busy。不同批次仍各自使用原 max_concurrent=4，不增加全组件并发配额、禁用层、调度队列或通用 manager。重复提交的公开 Promise 等待原上传真实完成，错误继续 reject；有效同会话的旧接受写入继续调用原刷新回调，退休访问的提示与关闭保持失效。

## Alternatives considered

只在有效 URL 应用时记值不能区分 A→暂缺 C→A；每次列表刷新都重新应用 URL 又会覆盖用户选择。因此 URL 访问身份与元数据可用性分别判断。

新增全局 disabled 能隐藏队列 B 按钮无反馈，却缩窄原有可用性；只保留一份 acting 显示值也不能表达 A、B 各自的 busy 与释放。文档请求表是现有页面动作的直接状态，没有共享管理层。

上传时只把全局锁在 datasetId 变化后清空可以恢复部分路径，但仍吞掉同范围的不同 File 批次与重开的确认访问，也让重复调用提前完成。原实现的同字节可用性对照证实这些批次原本允许，因此按实际批次复用 Promise，不引入新组件级限制。

## Consequences

Root 两条冻结探针的 case AST 保留；原 028dd fixture 的既有 case 输入与断言保留。新增对照覆盖初始数据 pending／暂缺目标后到达、元数据刷新保留手选、同文档同步去重、A 完成不释放 B、两个调参目标、规则管理自身忙状态、新上传访问、不同真实 File 批次、重复完成 Promise 与旧失败不释放新上传。

原 8d48、028dd、170 项 authority、110 项原始回放与旧候选 race 证据均保持，补丁从 028dd 单独投影。最初两个路由到达对照在 act 内等待 DOM 通知而阻塞，修正为冲刷 React Query 下一任务通知后在未修生产父版本通过；这两项不是生产缺陷。

验证仅使用受控 React DOM、File、QueryClient、真实认证存储和静态源码／类型门禁；不启动服务、浏览器或新 surface，不发真实 HTTP，不执行 Python 业务、测试、SDK、模型、数据库、正则或 callback。
