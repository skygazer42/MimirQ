# Agent Note: 登录入口结果的访问与会话归属

Status: implemented

## Problem

账号密码、SAML 和 OIDC 登录的异步结果直接建立会话并导航。在请求未完成时，页面卸载或用户显式登录另一个账号，旧结果仍覆盖当前凭证。账号密码表单还仅用 React state 表示提交中，同步两次 submit 能发送两个请求；登录、首次设置再返回登录后，旧失败会重新出现在新表单。

## Decision

账号密码表单以组件内请求身份同步拒绝重复提交，并用当前表单访问和既有认证 session revision 判断结果归属。模式切换形成新访问，返回相同模式也不能复活旧成功或错误；原请求结束只释放其持有的提交状态。

两个回调页保留原有单次执行标记，并单独记录当前挂载状态。请求捕获现有 session revision，写入凭证、发布结果和导航前核对挂载与版本。挂载标记在 StrictMode effect 重放后恢复，因此当前有效请求仍只完成一次；真正卸载后的结果退出。

completeOidcLogin 的唯一生产消费者是 OIDC 回调页，函数本来就返回 session。凭证写入从库函数迁到该消费者的归属检查后，与导航同步执行；HTTP、transaction 消耗、返回签名和当前失败政策保持。SAML consume 和账号密码 API 原有协议保持。

## Verification

真实 React DOM、认证存储、SAML consume 与 OIDC complete 只在外部 API／fetch 和导航边界受控。固定原始源码上的八个回归失败、三个 StrictMode 正常登录对照通过；探针原字节和 JSON 另存外部证据，修复后原样重放。现有登录、首次设置、SAML 错误及服务端路由测试继续验证正常成功和失败。

## Alternatives considered

只在页面拦截 OIDC 导航改动较少，但库函数此前已经写入旧凭证，不能阻止账号覆盖。向库函数增加可选发布回调可以保留写入位置，但唯一调用方已收到 session，额外策略参数会继续让操作归属分散。复用既有返回值把唯一写入迁到实际页面消费者，保持一个凭证存储所有者。

仅用本地 effect cancelled 布尔值很短，但 StrictMode 的清理会永久废弃单次执行标记启动的请求；使用独立挂载 ref 保留当前有效的重放。仅比较 token 或账号也无法区分同凭证的显式新登录，因此使用项目已有 revision。

## Consequences

新增的是已复现的请求、访问和会话身份判断，没有新增管理器、Context、默认成功或备用认证策略。底层已发出的身份提供方请求仍按既定流程完成，只有结果发布受当前意图约束；不声称取消远端操作。三个页面需各自维护少量本地生命周期状态，换取凭证与导航在同一操作归属下提交。

相邻的[OIDC 刷新结果的会话归属](2026-11-04-auth-refresh-session-ownership.md)持有传输刷新和 profile 查询的 revision 规则，本入口继续消费它，不替换原决定。活跃笔记没有重复登录入口提案或 rejected 记录。未运行服务器、浏览器、真实身份提供方或 Python 业务。
