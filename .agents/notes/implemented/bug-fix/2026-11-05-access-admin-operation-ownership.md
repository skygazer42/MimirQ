# Agent Note: 访问管理页面的请求与草稿归属

Status: implemented

## Problem

组详情的 mutation 回调跟随当前 render 更新。成员移除请求尚未完成时切换组，旧响应会使用新组的缓存 key；旧组保存也会覆盖新组的编辑。新建组、保存组信息和添加成员在成功后统一清空输入，丢弃等待期间仍允许输入的新草稿。列表仅保存一个删除 ID，两个不同组同时删除时会提前解除其中一行的忙碌状态。

仅由 React pending 状态禁用按钮不能阻止同一 render 前的重复提交。页面卸载、认证替换或 QueryClient 清除旧实体后，旧 mutation 仍能发布提示、更新缓存和清理当前输入；queryFn 自己发布的失败提示也没有卸载归属。

成员权限页也在角色保存后无条件清理该成员的选择；保存与移除使用两个独立通道，同一成员可能同时收到两种写入。旧会话的角色或移除结果还能写入替换后的成员缓存，或在卸载后发布失败提示。

## Decision

两个组页面保留 QueryClient 作为远程数据来源，写操作直接留在各自业务 async 函数。每个函数顺读捕获当前挂载、实际认证 revision 和原 Query 实体，发出原 API 请求，再核对归属后更新缓存、提示和草稿。显式动作通过现有 QueryCache.build 取得或建立实体，不在空闲清理后吞掉新操作；已经在途的动作仍随原实体移除而退休。

成功写入在视图退出后的缓存完成部分由[缓存寿命](2026-11-05-access-admin-cache-lifetime.md)进一步约束：仍有效的原会话与 Query 可以使受影响缓存失效；提示、草稿、对话框和直接响应发布继续要求原视图有效。该细化保留本记录的同步互斥、草稿和身份决定。

RBAC 与 RTBF 共享成员 Query 的值按[成员缓存 DTO 契约](2026-11-05-members-query-cache-contract.md)统一为 API 原始 snapshot，各视图使用 select；原 key、成员读取上限与下游交互保持。

新建和保存使用原有独立忙碌范围；删除按具体组或成员使用同步集合，互不阻塞其他对象。异步完成只释放自己的标记；失败仍报告原 API 错误并保留输入。创建／添加按实际输入版本清理尚未修改的草稿，组信息保存只清理提交时仍是同一对象的编辑。

成员权限页的角色保存与移除直接使用各自业务 async 函数，共享按 user_id 的同步写入集合；不同成员仍可并行。保存只退休当前值仍等于已提交角色的草稿，期间改成其他角色的选择保留。保存中的成员暂时不能再次发起移除，沿用原入口和确认框表达忙碌，不改变禁止移除当前用户的解释与确认条件。缓存失效后不制造缺失列表的成功快照，仍经原查询重新读取。

邻域 useAccessAdminSession 只订阅已有身份事件并读取已有 revision，供三页使用显式 React key。组详情的 key 还包含路由 groupId，实体改变时结束旧组件访问。这个 Hook 没有请求、缓存、mutation、权限或全局状态管理。每个操作仍直接读取 revision，因此同账号显式登录虽不发布范围事件，也能退休旧响应；普通 setAccessToken 轮换保留当前编辑。查询消费原 signal，取消或会话替换后的失败仍抛出，只停止过期提示。

原 DOM、class、文案、确认框、路由、API 方法／字段、limit=500、本地过滤与分页顺序保持。SETTINGS_READ 仍控制页面入口；SETTINGS_WRITE、租户成员校验、ACL 及服务端冲突处理继续由原后端持有。没有权限替代层或默认成功载荷。

## Alternatives considered

- 继续通过 useMutation 的可更新回调读取当前路由和草稿，可以保持代码位置，却混淆请求发起与完成时的对象。直接业务函数在一次调用里捕获原归属，避免增加另一套 callback context。
- 禁用全部编辑并串行删除，可以绕开覆盖和重复请求，但会阻止准备下一次输入、阻塞无关对象。因此只同步锁定当前操作对象，并按提交对象或输入版本退休草稿。
- 仅比较 groupId 或账号字符串，能识别部分切换，却识别不了卸载后返回同 ID、相同账号重新登录和同 key 缓存重建，因此同时检查挂载、revision 与 Query 实体。
- 请求开始前要求缓存必须已有 Query，可以缩短判断，但空闲清理后仍有效的页面会吞请求。因此在动作边界建立实体，原在途实体退休规则保持。
- 新建通用请求 manager 或 Context 能减少几行判断，却会隐藏组创建、保存、成员操作的不同结果。共享内容仅限实际复用的认证事件订阅，写操作顺序仍在页面。

## Consequences

页面维护少量局部标记和草稿版本；已经被后端接受的请求不会随离开页面而回滚。新的写入口需要沿用自己对象的忙碌与结果归属。真实 QueryProvider、QueryClient 和原 Input／Dialog／AlertDialog／Select 在 happy-dom 中验证行为；API、通知、路由及无关权限／布局外壳受控，不能据此声称真实授权、浏览器视觉或服务器事务已运行。

三个完整页面共 1885 行，分组目录与成员权限两个完整业务提交。29 个新增行为用例在精确 f37de423b7fdb46d60b593e84bea49ba79418593 基线上 21 失败、8 个保留行为通过。组批候选及原控制共 21 个通过；最终组合验证随交付报告记录。普通 token 轮换、同账号登录、卸载并返回同组、在途 Query 移除／重建、空闲清理后新操作、不同成员并行、同成员互斥、后端冲突和禁止移除本人均有控制；静态类型、lint、格式与界面源码核对随交付证据保留。没有启动浏览器、服务、Python 测试、SDK 或真实访问管理写入。
