# Agent Note: JWT 目录同步遵循真实预算与失败边界

Status: implemented

## Problem

JWT 用户组同步用 `JWT_GROUPS_MAX_GROUPS or 200` 覆盖显式零预算，尽管下游解析器已经规定非正上限返回空。配置零后仍可能创建用户组及成员关系。

成员自动创建在数据库失败后静默返回 False，并压掉 rollback／close 异常；组同步也压掉 rollback 失败。编排层使用 debug 格式化原始异常，组同步自身则只记录异常类型，失败可见性与隐私规则不一致。

## Decision

同步直接对 Settings 的原生整数执行既有零下界和 2,000 上界约束，默认 200 由配置声明持有。零上限生成空组列表，并在创建 Session 前退出该项组同步。claim 规则、TTL、原解析／去重、租户过滤及成员自动创建的独立开关保持。

三个目录同步模块的 warning 实参只包含 tenant_id 与异常类型，不额外传入原始异常文本、堆栈、subject、组列表或 JWT。数据库异常可能包含 SQL 参数，因此保留类型级日志；现有全局日志上下文继续由原日志配置持有。成员创建失败先记录该类型，再 rollback 并按原协议返回 False；Session 创建、rollback 和 close 失败交给已有同步入口捕获并记录。组事务直接 rollback 后重抛，finally 仍关闭 Session，节流包装保留原可选失败策略。

编排仍先组同步再成员创建，两项开关与失败边界独立。签名、租户存在／成员存在检查、用户 ID 长度、VIEWER 角色、审计哈希及参数保持，目录同步结果不替代路由成员／租户／权限校验。没有增加重试、状态包装、管理类或身份默认值。

## Alternatives considered

- 保留 `or 200` 能容忍旧调用方的空值，但会覆盖已有的零上限语义，使用另一份写入预算。
- 仅在 None 时选择 200 可以保留零，但 Settings 字段本来是不可空整数，该分支没有真实输入来源。
- 完整异常堆栈更利于定位数据库故障，但可能携带组名或用户标识；现有组服务已要求不公开这些值，类型与租户日志保留定位入口。

## Consequences

显式零停止本次组写入，其他合法整数沿用原上下界。调用者不再依赖零被自动改写为 200 的行为；需要组同步时应配置正上限。

可选同步失败在默认 warning 级别可见，资源清理失败不再伪装为已经恢复。已验证身份继续进入原路由授权，创建失败不会补造成员。类型级日志比堆栈信息少，深入诊断需使用受控数据库日志或可复现环境。

核对实际 Settings 声明、解析器首个返回、SessionLocal 前的退出和已提交鉴权调用方；完整模块 AST 对照只允许预算兜底退出，其他函数、签名、查询和事务保持。限定 Ruff／格式、Python 3.11 AST／源码编译及 Note 门禁提供静态证据。按用户要求未新增、修改或运行 Python 测试，未执行 JWT 请求、组解析、数据库或目录同步；旧本地鉴权说明保留其原始归属。

失败边界增量核对三个完整服务和实际调用绑定；模块 AST 对照限定日志字段／级别与 rollback／close 政策，所有查询、角色、审计构造、设置开关、顺序和正常返回保持。日志实参核对只含 tenant_id 和类型名，未导入或执行同步函数、Session、请求或日志调用。本批静态证据不证明真实 JWT、数据库并发或故障恢复表现。
