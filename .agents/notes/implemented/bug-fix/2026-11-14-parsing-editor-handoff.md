# Agent Note: 解析编辑保留原文并按实际选择移交

Status: implemented

## Problem

解析编辑与治理移交把处理稿写成原文，空正文又在批量路径被跳过。库与队列两种表示用不同选择 ID，恢复源文件漏带阶段，候选数量和实际操作范围不一致。部分成功后，原选择和队列状态未更新，重试会再次处理已经完成的文件。

复制反馈的旧请求和定时器可以落到新文件；单文件解析器会改新上传默认；挂载偏好先写默认再读取保存值。知识库启动散落在工作台，patch 返回后可能继续使用新会话发 retry。移交期间移动目录还会取消正文写入，索引拒写却留下已提交的内存记录。

## Decision

单份与批量共用实际会话移交动作。处理稿和原文分别读取，保持真实空串/空白。当前数据范围的可治理候选从实际队列与库推导，用稳定库 ID 维持同一文档的选择；跨文件夹能力保留并显示其他目录数量，切换数据范围清空旧选择。逐项成功才退出选择，失败保留并明确文件名，重试只处理剩余项。

本地编辑保存读取真实原文，编辑旧运行只更新该运行。缺文档身份明确失败，删除没有生产调用支持的另建记录分支。复制状态、请求和计时器归编辑 Hook，内容/对象变化或卸载即失效。偏好挂载只读，用户输入才写；单项解析器只改该文件。

知识库启动统一归已有解析动作拥有者，复用页面控制器生命周期。每次等待后检查请求及身份归属；服务器已接收与本地状态写入失败分别反馈。Store 同步索引拒写恢复原内存集合；目录、解析器等独立 metadata 不取消待写正文，真正的新任务、来源或工作阶段更替才使旧正文失效。

四个无生产引用的旧面板及专属测试退休；旧侧栏、拖动显示状态和重复文件 ID 集合退出。实际工作台、上传、预览、下载及治理能力由已有入口继续提供。

## Alternatives considered

- 仅按当前文件夹批量处理，能少一层候选规则，但实际目录树允许同时选择多个文件夹的文档，会留下可选却不处理的入口；因此保留跨目录能力并明确数量。
- 每次正文或 metadata 更新都取消旧操作，代码表面更简单，却会在真实拖动目录时使已经开始的移交失败；按真实任务状态、来源和阶段区别取消边界。
- 沿用分开的单份和批量函数能少改调用方，但原文、空串、状态和失败规则已经分叉；只有重复的实际业务移交流程合并，不建立通用任务框架。
- 所有移交强制持久化可统一提交承诺，但已有内存模式是明确保留的工作方式；本篇只要求实际成功确认和错误可见，不新增跨 IndexedDB/LocalStorage 的原子事务承诺。

## Consequences

原文、选择身份和版本语义保持，部分失败可直接重试，独立目录更新不打断正文。代价是批量需要逐项确认并在请求返回后读取当前事实；错误消息携带具体文件。可选缓存失败仍可按既有内存合同工作，用户明确保存才要求持久化。

203 项定向和最后 135 项反馈/清理回归通过；完整测试低并发运行的 197 文件、1,518 项通过。桌面和手机通过真实复制/下载、编辑、移交与刷新读回，跨目录部分失败和实际拖动交错也通过。HTTP 是 fixture，浏览器原生存储真实。默认并发一轮曾以 Windows 原生崩溃码退出，失败日志保留，不作通过证明。

本篇不证明真实服务、解析器或生产构建已验证；当前固定写法、命名和覆盖范围见 .frontend-structure/20261112-full-frontend-guidelines/parsing-editor/。全前端规约目标继续进行。
