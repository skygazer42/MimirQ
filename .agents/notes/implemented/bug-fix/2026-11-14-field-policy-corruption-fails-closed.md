# Agent Note: 损坏的字段权限配置不能变成未配置

Status: implemented

## Problem

FLS 元数据解析把模型校验和规则校验的全部异常转换成 None。表格和数据库目录入口把 None 当作没有字段策略，因此已配置但损坏的规则可能返回未脱敏数据。非对象配置也直接走同一放行路径。

## Decision

只有字段未提供或显式为 None 才表示没有策略。已配置的值先通过原生 FlsPolicy 校验，再执行已有的版本、规则 ID、白名单、长度与正则安全规则；失败直接传播，不合成无策略结果。匹配阶段也不吞正则错误继续放行。

内部直接读取 Pydantic 已建立的规则、字符串和列表，删除重复类型探测、字典转规则及空集合回退。掩码先在策略边界规范化；第一条匹配规则、账号与角色放行、默认掩码、短结果行和原数据复制保持。删除没有生产调用方的元数据包装函数。

## Alternatives considered

保留解析失败返回 None 可以继续读取坏配置的数据，但无法区分未配置和无法执行权限规则，会隐藏安全状态错误。返回一个空策略也有相同问题，因此使用明确失败。

## Consequences

损坏的持久配置现在阻止响应，原来的成功响应可能变成入口错误；本次没有给内部损坏状态新增客户端 400／422 映射。正常未配置、空规则、有效策略和请求模型的字段与错误格式保持。

19 个原／现源函数代表验证未配置、坏形状、坏版本、坏正则、重复规则、白名单、掩码与复制。数据模型使用真实 Pydantic 声明；正则端口仅处理固定字面夹具，没有运行正则引擎、数据库、HTTP、应用测试或真实权限请求。原失败证据与修后证据分别保留。
