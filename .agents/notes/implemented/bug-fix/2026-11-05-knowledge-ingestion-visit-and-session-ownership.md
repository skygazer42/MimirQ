# Agent Note: 知识库导入与入库动作分别持有会话、访问和原查询

Status: implemented

## Problem

操作页把已接受的 pending／running 连接器任务继续记为提交中；手工同步没有检查 React Query 的 refetch 错误，失败也提示成功。数据集元数据刷新会重新应用 URL 初始值，覆盖用户显式选择。已经离开的上传任务还会发布结果、导航，并刷新后来选中的查询。

详情抽屉跨文档保留版本选择和 diff，旧成功或失败会进入新文档。四种导入弹窗与拖放确认的旧完成会清空、关闭新草稿；disabled 不能阻止同一事件批次中的重复提交。隔离队列的放行、重试和调参在显式登录替换后仍执行余下写请求，旧调参完成还能关闭新访问。

反馈详情另写了一份生成回归用例的逻辑，遗漏 Demo 写保护。回归结果和 finally 的处理中状态没有归属，旧 A 会覆盖新 B；归档完成刷新的是后来选中的评分查询。入库监控的乐观处置长期覆盖服务器状态，旧失败还能回滚新决定；反馈与文档主查询失败被显示成空数据。

## Decision

动作直接捕获现有 getAuthSessionRevision。显式登录替换使旧动作失效，普通 token 刷新保留原动作。隔离复合动作在每个 await 后检查原会话，再决定是否允许下一次写入；已经接受的写入不回滚。同一个提交引用同步阻止重复事件，finally 只释放自己的处理中状态，释放本身不要求会话仍有效。

页面数据集访问、导入弹窗开关和选中范围、拖放确认以及调参访问各自持有本地请求身份。详情抽屉以 open 和 documentId 为现有内容组件的 key，每次访问重新建立版本选择与 diff 状态。没有增加通用 Hook、manager、Context、备用接口或新的业务流程。

UI 发布与接受写入后的缓存义务分开判断。有效同会话的旧上传仍刷新原数据集；操作页、详情、监控上传完成和反馈归档使用捕获的既有 query key，exact 匹配并刷新保留的原查询。导入弹窗保留既有 loadDocuments／loadConnectorRuns／onAfterImport 回调，但只有当前访问可以清空草稿、关闭弹窗、显示提示或导航。提示里的查看任务动作也保留原会话约束。

真实 useConnectorRuns 与三个导入入口的组合 RED 证明，旧 loadConnectorRuns 会把父视图切回 A。Hook 继续复用已有 fetchRunsForScope，只在第二个内部动作参数 selectScope 不为 false 时更新可见范围；原调用默认行为不变。三个已接受导入的回调传入 false，实际 LoadConnectorRuns 类型同步到弹窗和 Workbench 调用方。手工加载、现有五秒轮询及原取消／重试／续跑继续使用原行为和 query key／新鲜度规则。这两处范围外依赖是必要局部迁移，不重计类别所有者。

隔离队列刷新同样捕获原查询 key，并读取这些实际查询的 total；原查询失败继续走既有错误记录与提示。队列访问更换后，旧刷新不修改新访问的同步说明。删除只关闭仍属于原审核访问的抽屉，旧删除不关闭后来选中的记录。

连接器 POST 已返回时，pending／running 表示后台任务已接受，表单提交结束；后台进度仍由既有执行监控承接。手工同步使用 React Query 的 throwOnError，按真实结果提示。URL 数据集种子每次路由值只应用一次，列表元数据变化不重新覆盖显式选择。

监控处置按当前数据集、模式及预检运行保存临时覆盖。每个对象的请求身份阻止旧失败回滚新决定；成功后移除临时覆盖。执行文档使用实际 patchUserMetadata 返回的完整 Document，只在原查询中原文档对象仍未被更新时替换该行；新的服务器快照保持权威。预检样本继续依赖真实服务端复读，没有拼接带文件／配置指纹的伪记录。文件大小、mtime、SHA、原始配置验证、并发四、轮询与重试策略保持。

反馈列表和详情共用原生成函数，Demo 只提示；实际回归确认与 feedback ID 关联，并按当前访问发布。两个主查询沿用现有错误格式，增加局部错误提示，既有可选观测数据失败降级保持。

## Alternatives considered

只检查 mounted 能阻止卸载后的更新，但不能区分同一组件里的 A→B→A，也无法识别同账号重新登录。只依靠 disabled 或 React loading 状态存在同步事件窗口，故使用每个现有动作的局部请求引用。

把旧完成全部丢弃可以避免覆盖新页面，但会漏掉有效同会话已接受写入的缓存刷新；只保存 observer.refetch 又会跟随新的 observer options。原查询刷新和当前 UI 发布因此分别判断。

重建完整文件记录或以文件名、大小和修改时间充当内容身份可以减少比对，但会伪造配置归属，不能区分相同元数据的新 File。实现保留实际 File 对象及其字节，也不制造新的客户端指纹。

## Consequences

受控 React DOM、File、认证存储和 QueryClient 用例先在原实现记录 RED，再验证修复；HTTP、重型视图和交互原语适配层被替换。操作页十三项、详情七项、四种导入及真实 Hook 组合十九项、拖放五项、隔离十一项、反馈七项、监控十一项分别验证；原 Hook 生命周期十三项另行通过。原有用例输入和断言保留；新增适配层、真实 DTO 必填字段与错误文案断言的修正单独冻结，不能算作生产缺陷。

自查发现，详情动作改为等缓存刷新后再提示时，会在刷新期间显式更换会话后迟到提示。独立探针在原实现通过，在中间候选失败；两种动作现在也在刷新之后重新检查原会话，并按请求身份释放按钮。原实现完整回放一百一十项，其中四十七项生产缺陷 RED、六十三项对照通过，55 份生产源文件恢复哈希一致；这个候选回归另行保留，不能并入原有四十七项缺陷。

验证没有启动服务、浏览器或新 UI surface，没有真实 HTTP、原生 canvas、视觉或 hydration 验收，也没有执行 Python 业务、测试、SDK、数据库或模型。主查询错误提示属于有 RED 的行为修复，后续纯风格比较从这些修复后的固定提交开始。
