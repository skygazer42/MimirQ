# Agent Note: 缓存公开能力与读取边界

Status: implemented

## Problem

缓存模块保留没有生产引用的统计、压力、过期修剪和全库清空，掩盖实际正文/源文件与范围清理职责。读取把未知 IndexedDB 记录直接断言类型，坏正文或 Blob 进入上层流程；局部合并同样先信任存储结构。空身份静默返回又会把调用错误表现成成功或 miss。

预取和查看器把有明确截断标记的预览写成完整正文。即使响应未截断，较早发出的预览还会在本地确认保存后覆盖缓存；内存暂时保留新值，刷新恢复却变旧，显式空串也会丢失。

## Decision

删除已核实无引用的能力和私有支撑，仅公开真实调用合同。读取及同事务合并在实际缓存边界验证未知记录，类型从同一结构推导；保留真实空串和零值。空身份明确失败，scope 清理沿真实存储键执行。复用现有事务错误、取消和连接清理拥有者，不引入备用存储或通用 manager。

预取和查看器都只接受 available 且两种截断标记均为 false 的完整正文用于填充缓存。预览仍在查看器中正常展示；读取和填充的可选故障记录现有日志，不阻断实际服务器结果。

完整工作副本由确认型 `updateDocContentInCache` 拥有；省略字段、明确清空和完整双字段替换保持各自语义。原预览替换方法改为 `cacheDocContentIfMissing`：同一 readwrite 事务先 get，只在 native undefined 时 put。已有记录包括真实空正文都不被预览改写；取消与范围失效仍由已有 guard/signal 负责，不增加逐文档版本表。

## Related decisions

本篇部分接管[局部缓存写入](2026-11-12-browser-cache-partial-writes.md)的原预览完整替换入口；确认更新、局部合并、接管/取消和已应用补丁合同保持，完整双字段确认更新仍可修复坏记录。[失败恢复与目录提交](2026-11-14-parsing-failure-recovery.md)的加载事实、原始索引保护及目录回滚保持。检索活跃笔记没有需要拒绝的相反提案，不归档这些仍有独立作用的记录。

## Alternatives considered

- 保留未用导出可以服务未来界面，但当前没有入口、调用或需求；它们扩大了需要维护和解释的公开面，依用户先删后改的要求退出。
- 在每个页面重新验证只修局部读取，改动小，但存储还由预取、Store 合并和解析恢复共同消费；边界统一验证后内部使用具体类型。
- 保留空身份的静默返回可以避免异常，但真实调用者只提供文档身份；无效调用不应伪装缓存 miss 或提交完成。
- 给每个预览请求再维护正文修订表也能拒绝旧响应，但已有工作副本本来就应由明确确认更新接管；原子缺失填充直接表达实际边界，无需再同步一套版本状态。
- 取消所有预览缓存写入可以避免覆盖，但会退出实际使用的缺失缓存预热；保留原子缺失填充，完整/截断与确认更新分别处理。

## Consequences

无入口能力退出；保留能力的读取、写入和失败边界更明确。坏记录保持原文并可在真实修复后重读，用户确认的新正文和空串不会被可选预览覆盖。代价是外部结构需要真实 schema，缓存填充需要一笔原子检查；没有新增存储源、依赖或长期检查体系。

原生请求成功与事务完成不同；游标 continue 后不能再读 pending 的 request.result。既有事务入口处理提交和清理，范围删除基于主键；测试替身维持对应语义，原生浏览器另外验证实际结果。可选内存模式和必要缓存错误的区别保持。

具体源码/命名、独立进程内重放、原生浏览器与检查记录位于 `.frontend-structure/20261112-full-frontend-guidelines/cache-api/`。这些结果不能代表其余大型查看器或全部前端已经验收。
