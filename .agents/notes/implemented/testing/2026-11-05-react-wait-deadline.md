# Agent Note: React 等待断言先读取完成的更新

Status: implemented

## Problem

全量前端测试中的治理分页用例渲染 200 条文件后超过一秒，等待辅助函数在 React act 返回后直接检查循环期限，抛出渲染前保留的断言错误。单独运行同一用例通过；这条失败不能证明分页丢失了数据。

## Decision

waitForAssertion 在每次 act 完成后先执行调用方断言。当前状态已满足断言就返回；仍不满足且期限已到才抛出最后一个断言错误。期限内仍用既有零延迟定时器让出执行权，没有增加等待时长、重试业务请求、修改分页数据或放宽断言。

renderHook 的真实 React 根、结果引用、rerender、可选 wrapper 与卸载职责保留。新的回归用真实 Hook 状态更新，并在定时器中模拟时钟跨过期限，确定性覆盖“已完成更新”与“始终未就绪”两个结果，不靠机器负载和额外睡眠复现。

## Alternatives considered

- 增大分页用例的等待时间能减轻繁忙机器上的失败，但不能修正完成更新后抛旧错误的辅助函数语义，因此维持原期限。
- 将分页 mock 改成按 skip 返回能支持重复查询，但该用例的数据集签名不变，实际失败来自期限检查顺序，没有修改业务 fixture。
- 修改生产分页逻辑会扩大行为范围；[治理工作台的重置意图与文档同步](../bug-fix/2026-11-05-governance-parent-workflow.md)的完整分页和取消策略仍成立。

## Consequences

辅助函数允许读取已经完成的当前状态，同时保留未完成时的原错误。act 本身仍不可抢占；期限约束等待更多更新的时间，不会中断同步 React 渲染。辅助函数及实际消费者继续通过既有 DOM 测试验证，不据此声明真实浏览器或后台服务验收。

活跃笔记按 helper 名称、期限和断言机制检索，没有同一等待契约的既有决定；治理父面板笔记仅记录业务行为，继续保留，不吸收或归档。
