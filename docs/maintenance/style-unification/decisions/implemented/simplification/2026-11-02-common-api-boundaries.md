# Agent Note: 通用 API 在真实边界校验并保留内部类型

Status: implemented

## Problem

认证依赖将已经验证的租户 UUID 转回字符串，后续日志、请求状态及可选数据库工作又分别重新转换。通用校验模块提供五个没有调用或注册的错误包装，中间件则把已声明配置和限流器属性再次当作未知对象读取。这些写法增加了主流程中的适配步骤，也使输入边界和内部不变量混在一起。

## Decision

JWT claim 和请求头仍在认证入口解析；成功后内部直接传递 UUID，请求状态存 UUID，日志边界输出字符串。空值、无效值、租户不匹配的既有 400／401 响应与缓存策略保留。可选成员供应和组同步仍在原线程边界执行，其既有 best-effort 范围保留。成员供应和配额政策继续由[权限与配额决定](2026-11-02-permission-quota-contracts.md)约束。

未被跟踪源码导入、调用、动态命名或注册的 error_handlers 模块及五个包装退出；API 和业务直接使用实际错误所有者。共享异常只清理内部已确定类型的重复识别，JSON 脱敏、500 处理、认证头和请求 ID 传播保持现有形式。

请求中间件使用框架的 ASGIApp 和 RequestResponseEndpoint 类型。有锁、缓存、Redis 客户端和令牌状态的三个限流类保留；限流失败响应直接读取两种限流器都声明的属性。上传流累计、请求头清理、拒绝响应、Redis fail-open、日志节流和中间件注册顺序保留。

应用入口直接读取声明配置，目录和租户 ID 使用实际类型。初始化及关闭顺序保持原样，按开关加载的重依赖继续局部导入。根路由和健康探针补返回标注时显式指定 response_model=None，以保持原来未启用响应模型推断的行为和接口描述。

## Alternatives considered

- 保留字符串作为内部租户 ID 能减少本批差异，但会继续在同一条已验证链中往返解析；UUID 直接表达本批调用方共同要求的值。
- 将所有 UUID 入口统一交给 FastAPI 声明校验能减少辅助函数，但会改变已有 400／401 表现，并影响无效缓存回退；外部解析仍留在原入口。
- 保留无调用的通用错误包装可以为将来复用预留入口，但当前没有实际所有者或调用需求；需要新规则时应按真实业务边界引入。

## Consequences

认证后的内部函数要求已验证 UUID，新增外部调用者需要在自己的入口适配。中间件签名和配置依赖可以直接追踪，状态、资源与失败政策仍由原类或入口持有，没有新增 Context、通用包装或模块。

本批 15 个保留模块通过 Ruff、格式和语法检查；33 个认证／异常函数、7 个完整中间件与完整应用装配分别通过明确规则下的 AST 比较。24 处错误响应构造、4 个认证／租户公开签名及 37 个中间件函数参数形状保持一致。探针的响应模型行为依据已安装 FastAPI 源码核对，未实际导出 schema。按用户要求未新增、扩写或运行 Python 测试，运行时回归仍未验证。

历史决定核对：权限配额篇与成员供应边界部分重叠，互链保留；数据集篇约束业务所有者、配置篇约束校验模块，均保留原归属，没有被本篇替代的提案。
