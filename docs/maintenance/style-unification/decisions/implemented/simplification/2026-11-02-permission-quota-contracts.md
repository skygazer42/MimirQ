# Agent Note: 权限与配额依赖已声明的类型契约

Status: implemented

## Problem

RBAC 在请求模型已验证角色后再次转换字符串，并对已声明的 ORM 属性使用动态读取。配额模块分别在同步和异步入口复制结果字段、限流错误与后端失败策略，随后又对自己生成的结果重复取默认值和转换类型。

## Decision

请求角色继续在 schema 的外部输入边界归一化，路由直接使用验证结果；权限判断由已有的 `role_allows` 负责。ORM 的角色与布尔列允许历史 NULL，因此角色空值处理和输出布尔转换保留。未知权限仍拒绝，最后管理员保护、行锁和权限清理事务顺序保留。

JWT 成员供应只在经过验证的租户与用户契约内工作。审计哈希计算一次，数据库工厂声明为 `Callable[[], Session]`。供应的可选性质、用户长度限制、租户存在性、已有成员处理、回滚及关闭政策保留。成员校验与本地引导的所有者仍见[数据集服务决定](2026-11-02-dataset-service-functions.md)。

QPS 结果由同一构造函数生成，并以 `TypedDict` 声明字段；同步和异步入口仍分别消费 `.check()` 与 `.acheck()`。429 判定和带证据的后端失败处理各有一个实现。配额关闭时不消费令牌，fail-open、可配置 fail-closed、503、Retry-After、缓存配置指纹与 Redis 参数含义保留。上传与嵌入的 SQL 聚合条件保持原样，工作任务继续捕获 `TenantQuotaExceededError`。

## Alternatives considered

- 保留四份 QPS 结果与两份限流错误可以减少函数调用，但字段及异常政策需要多处同步；当前已有重复，因此合并这些维护点。
- 让强制执行调用只读配额检查可以继续减少重复，但检查入口会吞掉后端异常并放行，不能承载 fail-closed 政策，因此两个入口各自执行 I/O，共享结果和错误规则。
- 用通用回调同时驱动同步与异步入口能合并更多行，但增加模式分支和调用间接性，因此保持两段可顺序阅读的入口。

## Consequences

内部依赖签名声明的字符串、数字、布尔值和 ORM 属性，不再接受任意对象后猜测其类型。外部请求校验、历史 NULL、配额禁用与已定义降级仍在真实边界处理。结果类型与辅助函数留在所属模块，没有新增业务层或配置框架。

本批只运行 Ruff、语法、签名与源码契约检查。21 个公开函数的参数形状保持一致，118 处可确定调用匹配签名；四个 RBAC 路由声明及错误载荷、三个 SQL 聚合函数源码保持一致，同步与异步入口在归一化 await 后的 AST 一致。按用户要求未新增或运行 Python 测试，运行时行为仍未验证。

历史记录核对：已有数据集决定涉及成员校验所有者，与本篇部分重叠，双方保留并互链；没有其他活跃权限或配额决定。
