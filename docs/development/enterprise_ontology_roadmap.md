**2026-11-27 进度。** 概念与文档来源绑定、普通 RAG 混合回答、结构化问数枚举边界和 Agent 聊天动作链路均已完成实现。当前两组 50 题与两组 15 题的本体＋RAG 均分别为 50/50 和 15/15，且未把对照组答对的问题变错。首字 P95 尚高于 4 秒；真实客户数据、外部生产写入和回写状态仍待生产环境验证。下一阶段继续单独治理延迟，不把已完成的小样本 UI 试验当作生产结果。

**2026-11-26 优先级校正。** 先处理普通聊天与流式聊天的本体短路、领域定义与任务覆盖缺口，再推进后续扩展。新增研究依据和拟议顺序见[本体与 RAG 原文核对](./ontology_rag_research.md)。已有两跳、小样本和动作夹具只证明各自的局部契约，不能宣称 OA-RAG、OG-RAG 或通用融合已经完成。后续评测明确采用 GLM 构造候选、DeepSeek 作答、Qwen 语义审核，确定性事实另由执行器校验；历史全量主要使用 DeepSeek 自评的事实继续保留。

## 两到四跳取证

- `QuestionPlan.relation_path` 保存问题明确要求的两到四个有序关系标识。问答在已发布本体上核对起点类型、方向和中间类型。未指定路径的查询沿用现有入口。
- `read_ontology_citations` 按知识库、文档权限、版本、当前处理批次和适用期读取生效证据。查询从一个单字段业务主键出发。相邻两段只有在完整业务主键相等时才连接。每次答复选取一条可核验的路径，按行进顺序返回每段的原文引用。
- 会话回读继续用原计划和证据摘要复查。任一段证据失效时，路径结果不再回显。旧计划缺少路径字段时仍能按原摘要读取。
- 回归在挂载的问答入口用工单、设备和产线验证正确路径，并放入同名干扰和断链样本。用相同断言驱动硅基流动实测，并把验证结果记录到本体验收记录。

两跳取证已交付，评测已扩展到七道维修场景标注题。普通 RAG 和本体 RAG 使用相同文档与问题，按业务事实计算答案正确率、引用准确率、引用召回率与无证据误报。评测脚本以本体结果是否符合标注作为退出条件。 [评测入口](../../scripts/smoke_enterprise_ontology_rag_eval.py)

## 授权分组问数

指标通过 `dimensions` 声明分组属性，工作台高级定义可以保存维度。指标 API 和聊天使用各来源的授权查询执行分组，已发布本体预览和普通聊天显示分组表。同一未分组指标可比较两个明确且互不重叠的时间窗，两期沿用同一口径与权限。只有两期数据都完整时才提供差值，基期为零时省略变化率。派生指标的 `formula` 可引用一个已发布的基础指标，通过 `difference`、`ratio` 或 `percent` 组合两份授权数据。数据不足或除数为零时返回原因。维度层级仍待实现。 [问答规格](./enterprise_ontology_spec.md#问答文书与执行)

## 规则候选与工具

「企业本体」的「抽取与版本」可对文档或样本生成带原文的规则候选。管理员核对原文及条件后将候选加入草稿，发布时复查同一规则内互相矛盾的字面条件。Agent 的工具注册表提供 `query_ontology`，使用调用者已选的知识库与文档范围，返回授权查询结果或供用户预演的动作建议。动作执行继续使用既有审批和回执接口。

## 多动作流程

在「行为定义 → 高级定义」使用 `action_workflows` 引用已定义的动作。发布版固定步骤顺序，每个动作沿用自己的参数、前置规则和审批要求。

```yaml
action_workflows:
  finish_order:
    label: 完成维修工单
    actions: [record_review, close_order]
```

「版本应用 → 动作流程」按动作配置收集每步输入，创建请求后固定输入。当前步骤成功后才开放下一步。派发结果未知时查询原回执。流程请求可按 ID 重开，停止流程后仍可查已提交动作的回执。补偿需要目标系统提供相应的业务动作。
