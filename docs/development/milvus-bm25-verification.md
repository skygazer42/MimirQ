## 定向验证

- 原生 BM25、实际 CorpusIndex/通道、HTTP 503、数据库范围/回填、聊天记忆：33 项通过。
- 后端选定 35 个文件：340 项通过，42 个在原项目复现的旧失败单独排除。
- 真实 pymilvus 2.6.11 验证中文 analyzer、BM25 function 和稀疏倒排索引参数，文本查询不在 API 计算 sparse 权重。SDK 与缺少的 cachetools 安装在临时验证目录，原虚拟环境未修改。
- SQLite 执行实际 SQLAlchemy 查询，覆盖租户/会话/数据集/文档范围、近期窗口、中文及字面通配符。回填排除草稿、禁用、归档及旧流水线分块；该回归先失败再通过。
- 缺少或不匹配的全文集合沿实际通道向上报错，并使用现有统一错误层返回 `BM25_INDEX_NOT_READY` / HTTP 503。
- 实际应用 OpenAPI 导出通过。其余静态检查与独立审查结果在完成后补充。

## 既有失败与测试调整

本地模型退出验证中已有的 25 个后端失败继续沿用，见[原验证记录](./local-model-retirement-verification.md)。另对 `tests/test_robustness_redundancy_fixes.py` 在原项目和本批树分别运行：17 个失败的名称集合完全一致，主要涉及已退出的 local provider、旧查询所有者 monkeypatch 和缺少旧 get_vector_store 导出。未恢复旧导出或放宽配置来取得通过结果。

选定文件、42 个基线失败及其中本批逐项比较的 17 个失败名称保存在[测试清单](./milvus-bm25-test-selection.json)。运行 pytest 的排除表达式使用不带参数后缀的测试名，避免 HTML/括号等参数文本影响 `-k` 解析。

删除的测试只验证已退出的本地 BM25 缓存、锁、懒构建和重建机制；稳定作用域、版本 token 复用与失效测试转到实际 CorpusIndex 所有者。回填上限测试继续覆盖读前与读后的上限，以及超限前不得写入 Milvus。新的服务端范围、写入、删除和 SQL 测试覆盖迁移后的行为。

## 真实服务和迁移边界

配置的 Milvus 端点只做了只读连接探测，结果超时。没有启动服务、创建真实集合、下载模型、执行回填、重新计算 Embedding 或清理现有数据。真实 Milvus 的建索引、中文召回、统计范围变化和性能仍需在部署环境验证。

已有文档必须显式执行[回填流程](../guides/milvus_bm25.md)；新上传初始化集合不能替代历史回填。requirements 变化不卸载现有环境里的包。独立全文集合不改变现有语义向量集合，写入与失败重放仍遵守现有跨库索引一致性政策。
