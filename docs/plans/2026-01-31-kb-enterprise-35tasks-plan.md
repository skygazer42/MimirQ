# KB Enterprise Upgrade (35 Tasks) Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在不推翻现有架构（FastAPI + Postgres + Milvus + MinIO + Next.js）的前提下，通过 35 个可审计、可回滚的小任务（每任务 1 commit + push），把知识库项目在 **数据清洗 / 层级管理 / 可视化 / 工程化** 维度升级到更“企业级”的可维护与可运营状态。

**Architecture:** 继续沿用 `Parse → Governance → Chunk → Index` 主链路；新增能力遵循：
- **默认保守**：新增清洗规则/规则包默认关闭，仅在 profile / pipeline 显式启用。
- **可解释**：清洗命中、影响范围、统计指标可被导出与可视化。
- **分层可控**：目录树/分类树/治理 profile 继承，降低重复配置与维护成本。
- **小步快跑**：每个任务最小改动、TDD、完成即 commit + push（直接在 `main`）。

**Tech Stack:** Backend: FastAPI, SQLAlchemy, Postgres(JSONB), LangChain. Frontend: Next.js(App Router), Tailwind/shadcn, recharts/plotly.js.

---

## Execution Rules (User Choices)

- 分组顺序：A 清洗 → B 层级 → C 可视化 → D 工程化
- 新增清洗规则：**默认关闭**（只能通过治理 Profile 或 PipelineOptions 开启）
- Git 策略：**直接在 `main`**，每任务 **1 commit + 1 push** 到 `origin/main`

## Verification Commands

- Backend tests: `./.venv/bin/python -m pytest -q`
- Frontend checks (when touching `web/`):
  - `pnpm -C web lint`
  - `pnpm -C web typecheck`
  - `pnpm -C web test`

## Task Template (TDD)

每个任务都遵循：
1) 写/改 *最小* 测试 → 运行确保失败（RED）
2) 最小实现 → 运行测试通过（GREEN）
3) 必要重构（REFACTOR）
4) `git commit` + `git push origin main`
