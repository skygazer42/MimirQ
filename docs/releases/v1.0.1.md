# MimirQ v1.0.1 Release Notes / 发布说明

v1.0.1 is the current stable patch release. It keeps the v1.0 retrieval and
knowledge-pipeline behavior, while making a clean deployment safer to start,
operate, reset, and validate.

v1.0.1 是当前稳定补丁版。它不改变 v1.0 的知识流水线与检索口径，重点修复首次部署、
Docker 清理隔离、操作文档和检索界面交互问题。

## Snapshot / 概览

| Area | v1.0.1 outcome |
| --- | --- |
| First owner | Supports explicit `INITIAL_ADMIN_*` bootstrap and preserves fail-closed first-registration behavior. |
| Docker safety | Uses the isolated Compose project name `mimirq`; project cleanup no longer adopts or removes unrelated Dify containers. |
| Windows and Compose | Cleanup and optional parser profiles are portable across current Docker Compose implementations. |
| Operations | Adds one complete path from startup through dataset creation, ingestion, retrieval, cited chat, evaluation, backup, and troubleshooting. |
| Documentation UI | Adds four reproducible, redacted screenshots for the core knowledge-base journey. |
| Retrieval UI | Removes nested interactive controls that caused React hydration and accessibility errors in ranked results. |
| Route accuracy | Replaces the retired `/knowledge/retrieval` documentation path with `/knowledge` → **检索测试**. |

## Upgrade / 升级

No database migration is introduced by this patch. Back up the deployment,
pull `v1.0.1`, rebuild the API, worker, and Web images, then run the normal
readiness and knowledge-base smoke checks.

本补丁不包含数据库迁移。升级前仍应先备份，然后拉取 `v1.0.1`，重新构建 API、Worker
与 Web 镜像，并执行就绪检查和一次完整知识库闭环验证。

```bash
git fetch --tags
git checkout v1.0.1
make up-web
make ps
make api-ping
```

Do not use `docker system prune` as an upgrade step. MimirQ cleanup commands are
project-scoped; see the Docker guide before deleting volumes or images.

升级过程中不要运行 `docker system prune`。需要清空本地数据或镜像时，先阅读项目级
[Docker Compose 清理指南](../deployment/docker_compose.md#4-数据卷与清理)。

## Verification / 验证

- Backend release metadata, source guards, documentation links, and the current route contract are covered by automated tests.
- The Web retrieval result interaction is exercised in Playwright and rejects nested `<button>` controls.
- The four committed guide screenshots are generated by an opt-in, deterministic Playwright flow with public sample data.
- Chinese and English Docusaurus production builds both resolve the shared screenshot assets.

The benchmark methodology and measured v1 retrieval results remain those
published with v1.0.0; this patch does not claim a new accuracy or latency run.
See [the benchmark record](../benchmarks/changzhou_dify.md).

800 题方法与实测指标沿用 v1.0.0 已发布记录；本补丁不宣称新的准确率或时延结果。
